# 工作流 · 定义与实例

## 一、能力范围

蓝图（WorkflowDefinition）与实例（WorkflowInstance）模型、YAML/JSON 解析、磁盘持久化、内置种子。不负责引擎流转。

## 二、设计决策与取舍

- 每定义一文件 `definitions/{id}.yaml`；旧 `definitions.json` 启动迁移。
- 有序节点链为主干；**Gateway** 用 `kind`/`routes`/`defaultNext` 表达条件边，不引入图编辑器。
- **存储 SSOT**：`workflow-path.ts` → `{APP_DATA_DIR}/workflows`；Daemon 与 Electron 共用。
- 遗留双目录：SSOT 空且 legacy 有实例时一次性复制（不删 legacy）。

## 三、服务端规则

- `normalizeWorkflowDefinition`：prompt 数组 join；`maxRetries` 缺省 2；缺省 `kind=task`；gateway 校验 `routes[].next` / `defaultNext` 指向存在节点。
- 种子：`builtin_feishu_dev_pipeline`，仅 id 不存在时写入。
- 实例状态：`pending|running|paused|completed|failed`。

## 四、客户端流程

设置页「定义」Tab：编辑节点（排序、model、isolated、**kind/routes/defaultNext**、config）→ IPC 存 YAML。启动 → `createInstance` → `instances/{id}.json`。

## 五、接口

| API | 说明 |
|-----|------|
| list/get/save/deleteDefinition | 定义 CRUD |
| parseWorkflowDefinitionText | 自动 JSON/YAML |
| createInstance | 默认 maxSteps=50 |
| get/saveInstance | 实例 JSON |

IPC：`workflow:list-definitions`、`workflow:save-definition`、`workflow:run` 等。

## 六、数据

**Definition**：id, name, description?, workingDirectory?, config?, nodes[], 时间戳。

**Node**：id, name, prompt, model?, maxRetries, isolated?, **kind?**（`task`\|`gateway`）, **routes?**（`{when,next}[]`）, **defaultNext?**。

**Instance**：workflowId, status, currentNodeId, context, nodeHistory, notifyChatId?, workingDirectory, input?, maxSteps, stepCount, sessionKey?。

**NodeExecution**：nodeId, attempt, status, input, output?, rejectReason?, rejectFromNodeId?。

```
workflows/definitions/{id}.yaml
workflows/instances/{uuid}.json
```

## 七、非功能与可观测

读写失败静默降级；YAML `lineWidth: 0`。Gateway 缺省 task 不写出，保持 YAML 简洁。`APP_DATA_DIR` 未设时读写 no-op。

## 八、推送

无

## 九、已知限制与 TODO

- UI 存对象非 YAML 文本；与 MCP/斜杠 YAML 创建路径并存。
- `sessionKey` **不**写入 `session-routing.json`。
- Prompt 内 `{{config.xxx}}` 由引擎 `applyConfigPlaceholders` 二次替换（见 [03](./03-节点执行与流转.md)）；缺失键→空串 + WARN。
