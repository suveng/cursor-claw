# 工作流 · 触发与管理入口

## 一、能力范围

创建/更新定义、启动/恢复实例、查询状态：设置页、`/workflow` 指令、`POST /api/workflow-signal`、`manage_workflows` MCP。不负责 Agent 侧 next/reject。

## 二、设计决策与取舍

- UI、指令、MCP `run` 均 `createInstance`+`startWorkflow`+`launchWorkflowAgent`（MCP 另 emit stdout）。
- **恢复 SSOT**：Electron（UI/斜杠）`resumeWorkflowInstance`；Daemon（HTTP/MCP）`resumeWorkflowAndEmit`；均调引擎 `resumeWorkflow`。
- 定义 CRUD：admin MCP + 斜杠 `create|update`（复用 `parseWorkflowDefinitionText`）+ UI 编辑器。
- `notifyChatId`：指令=触发者；UI=主用户通道。

## 三、服务端规则

**manage_workflows**：list/get/create/update/delete/run/**resume**/status。`create/update` 解析 YAML 或 JSON（缺参文案含二者）；`resume`→`resumeWorkflowAndEmit`。

**斜杠**：`/workflow create` 多行正文；`/workflow update <id>` 覆盖已有；落盘 `saveDefinition`。

## 四、客户端流程

`Settings`→「工作流」→`WorkflowPanel`：定义（含 Gateway 字段）、实例；**自动将中断的 running 标为 paused** 开关（`workflowAutoPauseStale`）；paused 详情可「恢复」。飞书 `/workflow ls|info|run|resume|status|delete|create|update`。

```mermaid
flowchart LR
  U[用户] --> S[设置页]
  U --> F[/workflow]
  U --> H[POST workflow-signal]
  U --> AI[Admin MCP]
  S -->|resume| WR[resumeWorkflowInstance]
  F -->|resume| WR
  H --> SW[resumeWorkflowAndEmit]
  AI -->|resume| SW
  WR --> ENG[engine]
  SW --> ENG
```

## 五、接口

| 子命令 | 说明 |
|--------|------|
| ls, info \<id\> | 列/查定义 |
| create / update \<id\> | YAML 或 JSON 正文建/改定义 |
| run \<id\> [输入] | 启动 |
| resume \<实例ID\|序号\> | 恢复 paused |
| status [实例ID] | 查实例 |
| delete \<id\> | 删定义 |

| 通道 | 契约 |
|------|------|
| IPC `workflow:resume` | `{ instanceId }` → `{ ok, error?, instanceId? }` |
| HTTP `POST /api/workflow-signal` | `{ action:"resume", instanceId }` → 200/400/404/409 |
| MCP `manage_workflows` | action 含 `resume`；`data` 为 YAML 或 JSON |

## 六、数据

读写 `{APP_DATA_DIR}/workflows/definitions` 与 `instances`；配置项 `workflowAutoPauseStale`（electron-store，默认 true）。

## 七、非功能与可观测

指令经 `reportCommandResult`；MCP 错误文本返回。排障：`workflow_storage_root=`；resume 结构化日志 `workflow_resume`（stderr）。

## 八、推送

run/resume 成功通知 `notifyChatId`。
