# 启动与自动重连

## 一、能力范围

Agent 拉起（`agent-sdk`/`session-dispatcher` 路由 sdk/cc/codex/opencode）、Prompt、Daemon 调度、崩溃自愈。Claude `query()`；Codex `runStreamed`；OpenCode `session.prompt`+SSE（`agent-opencode-sdk.ts`）。

## 二、设计决策与取舍

- **四引擎统一网关**：IM/任务/工作流/`/chat new` 经 `agent-sdk-http`；init 仅 `ensureAgentSdkHttpServer` 常驻。
- **长驻 Agent**：SDK/CC/Codex/OpenCode 默认 resident；`enterGuardWithLifecycle` 单飞（S8 busy IM）；超时各引擎 finalizer。
- **主进程续接（S7，四引擎）**：`recoverAllActiveRuns` 读快照；三引擎 guard 前探活+`classifyResumeFailure` IM（07–09）；`resume`→guard→续接 API；skip/failed 语义不变；`userStopped` 不续接。
- **ContextRotation**：≥90%×2、冷却 3min；各引擎清对应 sessionId。
- **群名/对方名（入队拼尾）**：Daemon `pushMessage` 入队前经 `resolveLaunchChatName` 拉名；有名则正文末尾 append `\ngroup_name: <名>`；`buildPrompt` 只透传队列正文。
- **SDK 冷启动进度（B2）**：`phase=starting` 期间 orchestrator 通知「正在连接 Agent…」；`launchSdkAgent` 在 create/limit 后通知「正在准备模型…」；`agent.send` 后「Agent 处理中…」。`buildEnqueueStatusText`：`phase===starting`→排队文案。
- **bind 后 SDK 预热（B1）**：`warmupSdkAfterBind` 挂 `initDaemonManager`/`resolveBindWaiter`/`completeBind`→`POST /api/sdk-warmup`；fire-and-forget，失败 WARN。

## 三、服务端规则

1. claim→launch/dispatch；`agent_busy` 延后。
2. 模型默认：SDK `composer-2`、Codex `CODEX_DEFAULT_MODEL_ID`；须配 API Key。
3. 超时 finalizer；非超时 `failedCooldowns`+长驻保留。
4. watchdog→cancel→finalizer。
5. 非 SDK 引擎 per-engine 端口 json 仅显式拉起 HTTP server 时写入；Codex/OpenCode 冷启动探活失败返回用户文案。

## 四、客户端流程

队列/SSE→300ms 防抖→claim→launch/dispatch→Run→complete→idle。SDK 首条冷启动进度：

```mermaid
flowchart LR
  enqueue[入队确认] --> connect["正在连接 Agent…"]
  connect --> prepare["正在准备模型…"]
  prepare --> processing["Agent 处理中…"]
```

三态 notify **不带** `message_id`/`stop_progress`，不触发 `stopSessionProgress`。

## 五、接口

| 入口 | 说明 |
|------|------|
| Daemon `/api/agent/launch\|dispatch` | IM（转发至 Electron `agent-sdk-http`） |
| Electron `POST /api/sdk-warmup` | Daemon `completeBind` 跨进程预热（→`warmupSdkAfterBind`） |
| `launchSessionAgent` / `launchIndependentAgent` / `launchWorkflowAgent` | 本地经 `launchSdkAgentFromHttp` 统一网关 |
| `launch*Agent`/`dispatchTo*Agent` | 四引擎长驻入口（网关进程内委托） |

## 六、数据

四引擎端口 json；四份 `*-active-runs.json` 快照；四引擎 session 类型（见 06–09）。

## 七、非功能与可观测

`dispatch_retry`/`watchdog`/`context_rotation`/`dispatch_failed`；`[compression]` UI 日志；`[recover]` 四引擎汇总（`recoverAllActiveRuns`）；bind/init 预热 `[sdk_warmup]`（Electron UI 日志 + Daemon WARN）。

## 八、推送

无。
