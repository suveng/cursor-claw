# 配置与更新

## 一、能力范围

应用配置持久化（`electron/config/config-store.ts`）、开机自启、关闭行为、代理、Daemon 端口、**崩溃分析目录**；系统托盘；应用内更新（`electron/config/updater.ts`）；**工作区注入（已废弃自动写盘）**。

## 二、设计决策与取舍

- **electron-store + encryptionKey**：名 `cursor-claw-config`。
- **自动注入废弃（T1）**：`injectWorkspaceToDir` / `injectWorkspaceMcpAndRules` 为 no-op；**launch 与 Daemon 就绪路径不得写** `~/.cursor` rules/MCP。
- **手动注入收窄**：IPC `workspace:inject` 仅写项目 admin Skill（`cursor-claw-admin/SKILL.md`）；`cleanupLegacyInjection` 可选手动清理历史 MCP。
- **平台差异化更新**：macOS Homebrew；Windows electron-updater。

## 三、服务端规则

无。Daemon 端口默认 `19528`，经 `LARK_DAEMON_PORT` 传递。

## 四、客户端流程

### 工作区注入（现状）

| 路径 | 行为 |
|---|---|
| launch / Daemon 就绪 | **不写盘**（no-op） |
| 用户 `workspace:inject` | 仅 admin Skill 到项目 `.cursor/skills/` |
| `cleanupLegacyInjection` | 可选清理全局/项目 MCP 中 cursor-claw 键 |

`resources/template/rule/cursor-claw.mdc` 为 **Legacy** 参考模板，launch 不自动注入；SDK 长驻 IM 主路径见 [Agent调度/03-启动与自动重连](../../业务域/Agent调度/03-启动与自动重连.md)。其余 `resources/template/` 仅供手动复制，不再自动写盘 rule/mcp。

### 崩溃分析目录

Settings general Tab「崩溃分析目录」：复用 `selectDirectory()` 选绝对路径，autoSave 写入 `crashAnalysisDir`；留空显示「未配置（跳过归档）」，Agent 失败时不写盘（依据：`Settings.tsx`、`electron/config/config-store.ts`）。

### Profile 级 Daemon 日志

Settings Agent Tab 各 Profile 编辑弹窗（`ProfileDaemonLogField`）可选 `daemon.log` 绝对路径，写入 `AgentResource.daemonLogPath`；留空走默认规则。Electron `ui-logger` 与 Daemon 子进程经 `electron/config/daemon-log-path.ts` 的 `resolveActiveDaemonLogPath` 共用路径：优先首个**启用通道**绑定 Profile 的自定义路径，否则 `{workspaceDir}/.cursor/daemon.log`，再否则 `{userData}/logs/daemon.log`。Daemon 启动时注入 `DAEMON_LOG_PATH`；Profile 日志路径变更后自动重启 Daemon。

### 更新流程

启动 4s 后 `electron/config/updater.ts` 的 `runStartupUpdateCheck`；Settings 手动检查/应用。

## 五、接口

| IPC | 说明 |
|---|---|
| `config:get/save` | AppConfig |
| `workspace:inject` | 仅 admin Skill |
| `updater:check/apply/current-version` | 更新 |

### AppConfig 关键字段

| 字段 | 默认 | 说明 |
|---|---|---|
| workspaceDir | "" | 主工作目录 |
| crashAnalysisDir | "" | 崩溃分析根目录；**空=未配置**，失败归档跳过 |
| AgentResource.daemonLogPath | 未设 | Profile 级 daemon.log 绝对路径；**空=默认规则**（见上文 Profile 级 Daemon 日志） |
| daemonPort | 19528 | Daemon 端口 |
| setupComplete | false | 允许自动拉起 Daemon |
| cliMigrationPending | false | 历史 CLI 绑定迁移后 Dashboard 一次性 Banner |

### AgentResource 与通道绑定

`AgentResource.type` 仅 `"sdk"` | `"claude-code"`（`channel-types.ts`）；**无**虚拟 `cli` 资源与 `CLI_RESOURCE_ID` 注入。`getAgentResource` 缺省回退首个 sdk/cc（`electron/config/config-store.ts`）。

通道 `agentResourceId` 须指向 sdk/cc 资源 id；启动时 `migrateCliBindings` 清理历史 `type:"cli"` 条目并将仍绑 cli 的通道改绑首个可运行资源，有变更则置 `cliMigrationPending`（依据：`electron/config/config-store.ts`）。

## 六、数据

userData 路径；profile 子目录 `cursor-claw-{profile}/`。

## 七、非功能与可观测

- 托盘双击恢复窗口；changelog 读 GitHub `changelog/`。
- `crashAnalysisDir` 非空时 Agent 失败由主进程 `electron/agent/shared/crash-log-archiver.ts` 的 `archiveAgentFailureLogs` 写事件子目录（见 02 §七）；未配置仅 WARN，不阻断 IM notify。

## 八、推送

`updater:status` / `updater:error` 到渲染层。

## 九、已知限制与 TODO

- T10 后 admin 控制层可能完全 HTTP 化。
