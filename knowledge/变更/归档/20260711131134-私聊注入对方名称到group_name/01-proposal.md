# 私聊注入对方名称到 group_name 产品需求文档

> **变更 ID**：`20260711131134-私聊注入对方名称到group_name`
> **来源**：kb-propose
> **类型**：Feature
> **优先级**：P2
> **外部 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无
> **修订**：Rev1（2026-07-11）— 注入口径改为「入队正文末尾」；废止 Prompt 首行验收（见 `07-prd-revisions.md`）

## 一、背景与问题

群聊/私聊场景下，agent 需要知道当前对话对象或所在群，以便正确理解上下文。

先前方案在组装 Prompt 时于**首行**注入 `group_name:`，经验证不生效。本变更改为：消息进入文件队列**之前**，将名称**拼到消息正文末尾**，使 agent 在用户消息正文末尾可见 `group_name`。

私聊无群名时使用对方显示名；若开通拉名能力需通讯录相关权限，应通过设置页既有「一键创建应用 / 扫码更新权限」自动带上，**不另开**手工申请路径。

## 二、目标与非目标

### 目标

1. **对话可识别名称**：飞书消息入队前，能取得名称时在消息正文末尾追加一行 `group_name: <名称>`（群聊=群名，私聊=对方显示名）。
2. **无名称时可预期**：拿不到名称时不拼该行，不写无效占位；解析失败不阻断入队。
3. **权限随扫码开通**：获取用户名所需权限纳入扫码创建/更新清单，管理员扫码即可开通。

### 非目标

- **不**再依赖 Prompt 首行 `group_name:` 注入作为产品验收路径。
- **不改** agent 执行引擎、会话隔离、IM 发送协议或其他通道契约（除入队正文末尾追加约定外）。
- **不要求**用户在飞书开放平台后台另行手工勾选/申请权限菜单。
- **不涉及**新页面或视觉改版。

## 三、用户与场景

### 用户

- **飞书私聊/群聊用户**：与机器人对话，期望 agent 知道对方是谁或所在群。
- **应用管理员**：通过设置页扫码开通/更新飞书应用权限。

### 场景 A：有名称（私聊或群聊）

用户向机器人发消息。系统能取得名称时，进入队列的消息正文在原有内容之后追加：

```text
\ngroup_name: <名称>
```

私聊为对方显示名，群聊为群名。Agent 侧应能在用户消息正文末尾看到该行。

### 场景 B：无名称

因权限未开通、名称暂不可用等原因拿不到名称时，**不拼**该行，不写无效占位；消息照常入队，解析失败不阻断。

### 场景 C：管理员扫码开通权限

管理员在设置页发起「一键创建应用」或「扫码更新权限」。扫码清单含获取用户名所需权限；完成扫码即可开通。

### 场景 D：群聊 / 私聊命名规则

- 群聊：使用群名。
- 私聊：使用对方显示名（不得用空群名冒充）。

## 四、功能需求

### F1 入队正文末尾追加 group_name

- 消息通道写入文件队列前，若能解析到名称，在消息正文末尾追加固定格式：`\ngroup_name: <名称>`。
- 键名固定为 `group_name`；群聊填群名，私聊填对方显示名。
- Agent 须能在用户消息正文末尾看到该行（不以 Prompt 首行为验收）。

### F2 无名称时的可预期降级

- 无法取得名称时不拼该行，不写无效占位。
- 解析失败不阻断入队。

### F3 权限纳入扫码创建/更新清单

- 若本能力依赖通讯录/获取用户名相关权限，须纳入「一键创建应用」与「扫码更新权限」清单。
- 管理员扫码即可开通；不另开手工申请路径。

## 五、非功能需求

| 编号 | 描述 |
|------|------|
| NF1 | 追加仅影响入队消息正文末尾，不改变用户可见的飞书消息气泡样式。 |
| NF2 | 权限开通路径与既有扫码体验一致，不新增独立申请入口。 |
| NF3 | 群聊用群名、私聊用对方显示名；无名不拼，不阻断入队。 |

## 六、验收标准

1. **有名入队**：飞书私聊/群聊且能取得名称时，入队消息正文末尾为 `\ngroup_name: <名称>`；Agent 在用户消息正文末尾可见该行。
2. **无名入队**：无法取得名称时不拼该行、不写占位；消息仍入队。
3. **扫码含权限**：设置页扫码创建/更新权限清单含获取用户名所需权限，用户扫码可开通。
4. **命名规则**：群聊为群名、私聊为对方显示名；解析失败不阻断入队。
