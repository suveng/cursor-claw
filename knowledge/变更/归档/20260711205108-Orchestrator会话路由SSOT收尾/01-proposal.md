## 一、背景与问题

Cursor Claw 采用 Electron 与 Daemon「双进程」协作：Daemon 负责 IM 入站、排队合并与 Agent 调度，Electron 负责 Agent 引擎执行与用户侧指令。此前架构演进已将 **IM 主路径调度** 的单一事实来源（SSOT）迁移至 Daemon；但 **「哪个会话当前活跃」以及「临时会话结束后应回退到哪个会话」** 的状态仍分散在两处：

- **当前活跃会话**：已由 Daemon 统一维护，Electron 通过接口读写。
- **活跃会话回退关系**（创建临时会话前记住的原活跃会话）：仍保存在 Electron 进程内存中。

由此带来可感知的产品问题：

1. **Electron 重启后会话回退失效**：用户通过 `/chat new` 创建临时会话后，若 Electron 主进程重启（应用更新、崩溃恢复、手动重启等），临时会话结束时无法自动回到创建前的原活跃会话，用户需手动切换，体验与产品承诺不一致。
2. **架构债务未闭环**：Daemon 已是 Orchestrator 与会话路由的权威侧，回退栈仍留在 Electron，与「IM 调度 SSOT 在 Daemon」的分工不一致，增加排障与后续迭代成本。
3. **关联遗留项未收尾**：前序「巨型单体拆分」变更将 `dispatchSessionAgents` 空实现记为 ponytail；本会话路由收尾变更负责清理该 dead code 并同步知识库，避免文档与代码长期脱节。

## 二、目标与非目标

### 目标（必须达成）

1. **回退栈 SSOT 迁至 Daemon**：临时会话创建时记录的「回退目标会话」由 Daemon 统一持有，Electron 不再在本地内存维护该映射。
2. **临时会话结束自动回退行为恢复且可跨 Electron 重启**：在 Daemon 持续运行、Electron 重启后，临时会话正常结束仍应自动切回创建前的活跃会话（前提：回退目标会话仍在运行）。
3. **行为不回归**：`/chat new` 创建临时会话、活跃会话切换、IM 主路径消息调度、定时任务独立触发等既有用户可见行为与现网一致。
4. **清理无效遗留**：移除已无实现的 `dispatchSessionAgents` 空壳及相关无效引用；知识库中活跃会话栈与定时任务调度描述与现网一致。

### 非目标（明确不做）

- **不改变**飞书卡片展示、Electron 界面布局或 `/chat new` 的用户指令语法。
- **不迁移** IM 主路径调度回 Electron（禁止回归 Electron 队列扫描）。
- **不在本期强制实现** Daemon 重启后会话路由的全量持久化；若实现复杂度超 scope，记 ponytail，但须在本变更 design 中明确边界。
- **不拆分** `daemon-manager.ts` 等历史超限文件（属其他变更范围）。

## 三、用户与场景

### 用户

- **飞书管理员 / 主用户**：通过 `/chat new` 创建临时会话处理单次任务，期望结束后自动回到原主会话。
- **运维 / 开发者**：通过定时任务独立模式触发临时 Agent，期望活跃会话切换与回退语义与手动创建一致。
- **工程协作者**：需要会话路由状态在 Daemon 侧可观测、可维护，避免「双大脑」状态分裂。

### 场景 A：创建临时会话并正常结束（基线）

用户在飞书发送 `/chat new <任务描述>`。系统创建临时会话、切换活跃路由至该会话，并记住创建前的活跃会话。临时任务完成后 Agent 退出，系统自动将活跃路由切回创建前的会话，并给出可理解的系统提示。**行为与现网一致，但回退关系不再依赖 Electron 内存。**

### 场景 B：Electron 重启后临时会话结束（核心修复）

用户在场景 A 中途因应用更新或崩溃导致 Electron 重启，Daemon 子进程仍运行。临时会话随后正常结束。系统仍应能根据 Daemon 侧保存的回退关系，将活跃路由切回创建前的会话（若该会话 Agent 仍在运行）。**修复现网「Electron 重启后回退丢失」问题。**

### 场景 C：定时任务独立触发临时会话

Daemon 定时任务以独立模式触发 Agent（经既有启动通道）。若触发时存在其他活跃会话，应记录回退关系并在任务结束后按与场景 A 相同规则回退。**与 `/chat new` 语义对齐。**

### 场景 D：无回退目标或回退目标已停止

临时会话结束时，若未记录回退关系，或回退目标会话 Agent 已不在运行，系统不强制切换活跃路由，不产生错误级中断。**与现网容错一致。**

## 四、业务流程

### 主流程：临时会话创建 → 切换 → 结束回退

1. **F1** 用户发起创建临时会话（`/chat new` 或等价独立触发）。
2. **F2** 系统校验参数与工作目录（沿用现网规则）。
3. **F3** 启动临时会话 Agent；若当前存在不同于临时会话的活跃会话，**记录回退关系**（临时会话 → 原活跃会话）。
4. **F4** 将当前 chat 的活跃路由切换至临时会话；向用户确认已切换及「结束后将自动回退」。
5. **F5** 临时会话 Agent 运行至结束（正常退出或用户停止）。
6. **F6** 系统读取回退关系；若当前活跃仍为该临时会话且回退目标仍在运行，**自动切回**回退目标并清理回退记录；否则静默跳过回退。

### 关键分支

- **F3-a（无原活跃会话）**：创建时当前 chat 无其他活跃会话或活跃即自身 → 不写入回退关系。
- **F6-a（活跃已被用户手动切换）**：结束时当前活跃已不是该临时会话 → 不覆盖用户选择，仅清理回退记录（若适用）。
- **F6-b（回退目标已停止）**：回退目标 Agent 不在运行 → 不切换活跃路由，清理回退记录。
- **F6-c（Electron 曾重启）**：F3 写入的回退关系在 Daemon 侧仍可读取 → F6 回退逻辑与 F6-a/b 相同，**不因 Electron 重启而丢失 F3 记录**。

### 不变路径（显式不改）

- **IM 入站 → Daemon 排队 → Orchestrator dispatch → Agent 回复**：主路径调度仍在 Daemon，Electron 不扫描 IM 队列。
- **活跃会话读写主接口**：仍经 Daemon 现有 active-session 能力；本变更仅扩展回退栈，不改变 IM 消息路由规则。

## 五、功能需求

| 编号 | 需求描述 |
|------|----------|
| R1 | 创建临时会话时，若存在可回退的原活跃会话，系统须在 **Daemon 侧** 持久化（进程内至少）该回退关系，键为临时会话标识。 |
| R2 | 临时会话正常结束时，系统须从 Daemon 读取回退关系并按 F6 规则执行自动回退；回退完成后清除该关系。 |
| R3 | Electron 重启不应导致 R1 写入的关系在 Daemon 仍存活时丢失（即 R2 在场景 B 仍成立）。 |
| R4 | `/chat new` 与定时任务独立触发（`__IND_LAUNCH__` 路径）须使用 **同一套** 回退记录与读取语义。 |
| R5 | 移除已无业务实现的 `dispatchSessionAgents` 空壳及无效 export/import；知识库中「活跃会话栈在 Electron」等过时描述须更新为 Daemon SSOT。 |
| R6 | IM 主路径不得回归 Electron 侧队列扫描或周期性 claim 调度。 |

## 六、验收标准

1. **回退基线**：主用户私聊执行 `/chat new`，临时会话结束后活跃路由自动回到创建前会话（回退目标仍在运行）。
2. **跨重启修复**：上述流程中 Electron 重启一次（Daemon 保持运行）后，临时会话结束仍能自动回退。
3. **独立触发对齐**：定时任务独立模式触发且存在原活跃会话时，任务结束后回退行为与验收 1 一致。
4. **容错**：无回退记录、回退目标已停止、或用户已手动切换活跃会话时，不报错、不错误覆盖活跃路由。
5. **架构约束**：IM 消息仍仅经 Daemon Orchestrator 调度；代码与知识库中无 `dispatchSessionAgents` 有效调用链；`05-定时任务.md` 调度描述指向 Daemon `runAgentDispatchLoop`（或等价现网入口）。
6. **工程规范**：变更代码含中文注释；单文件不超过 300 行；遵循各目录 AGENTS.md。
