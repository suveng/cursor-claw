## 一、背景与问题陈述

resume 三入口已落地；lite「工作流恢复债务清偿」仅清 D1/D3 文案。仍存：

1. **会话键未持久**：isolated 后 `sessionKey` 未可靠落盘，重启或跨入口 resume 时绑定丢失。
2. **存储双路径**：Electron `userData/workflows` vs Daemon `APP_DATA_DIR/workflows`，两套目录真相。
3. **字段类型未统一**：引擎字段类型口径不一致，恢复/信号与会话路由可能分歧。

导致 resume、信号与会话路由割裂：找错实例、丢绑定，或跨进程读不到实例。

## 二、用户可见症状

| 症状 | 典型表现 |
|------|----------|
| 节点会话漂移 | resume 后续聊落到错误会话 |
| 跨进程找不到实例 | Electron/Daemon 切换或重启后按预期路径找不到实例 |
| 运维两套目录 | 排障需双目录对拍，易漏查 |
| 绑定丢失 | isolated 后会话键未恢复，信号/路由无法对齐 |

## 三、目标与非目标

### 目标

1. **sessionKey 可持久**：落盘并可在重启后恢复。
2. **存储根统一或单一 SSOT**：Daemon/Electron 读同一真相；若保留路径差异，须明确 SSOT 与迁移口径。
3. **引擎字段类型一致**：实例/会话相关字段口径统一。
4. **入口兼容**：既有 resume 三入口与信号路径仍通。

### 非目标

- 不做分支 Gateway；不重做 YAML 节点引擎；不扩 `/workflow` create/update。
- 不替代 lite「工作流恢复债务清偿」文案范围。
- propose 阶段不绑定实现类名/路径/签名（归 `/kb-design`）。

## 四、用户与场景

- **使用者**：resume 后续聊回到原绑定会话。
- **跨进程**：Electron 与 Daemon 见同一实例真相。
- **运维**：按单一存储真相定位，不必双目录对拍。

| 场景 | 简述 |
|------|------|
| S1 | 重启后 sessionKey 可恢复并用于路由/续聊 |
| S2 | Daemon/Electron 读统一存储根或已声明 SSOT |
| S3 | 既有 resume 三入口仍命中正确实例 |
| S4 | 信号按持久会话键路由，不因类型分歧误路由 |
| S5 | 与 Agent 标识持久化不双写会话映射 |

## 五、功能需求

| 编号 | 需求描述 |
|------|----------|
| R1 | sessionKey（或等价绑定）可持久并重启可恢复 |
| R2 | 统一 workflows 存储根，或明确单一 SSOT + 迁移/对齐 |
| R3 | 引擎相关实例/会话字段类型口径一致 |
| R4 | 既有 resume/信号路径仍可用 |
| R5 | 与 Agent 标识会话映射职责不双写 |
| R6 | 不做 Gateway、不重做 YAML 引擎、不扩 create/update |

## 六、验收标准

1. **重启可恢复 sessionKey**：isolated 后落盘的键，重启后可恢复并用于续聊/路由。
2. **双端同一真相**：Daemon/Electron 对同一实例读统一存储根或已声明 SSOT。
3. **resume 仍通**：既有三入口仍能命中正确实例并完成恢复语义。
4. **非目标未扩大**：无 Gateway、无 YAML 引擎重做、无 create/update 扩面。
5. **无双写**：不与 Agent 标识持久化形成两套会话映射真相。
6. 代码含中文注释；运维可识别单一存储真相。

## 七、范围边界

**在范围内**：sessionKey 持久与恢复；存储根统一或 SSOT+迁移；字段类型统一；resume/信号兼容；与 Agent 标识职责协调。

**不在范围内**：分支 Gateway；YAML 节点引擎重做；`/workflow` create/update 扩面；lite D1/D3 文案项。
