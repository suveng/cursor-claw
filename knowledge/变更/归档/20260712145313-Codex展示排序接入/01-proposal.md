# Codex展示排序接入产品需求文档

> **类型**：功能
> **优先级**：P2
> **外部 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无
> **依赖**：`20260712113320-OpenCode展示排序接入` 已落地（可直接做）

## 一、背景与问题陈述

Presentation 展示排序（ordering）已在 Cursor、OpenCode 等引擎侧对齐：工具执行过程中正文不抢首屏，thinking/tool 与进度消息按统一口径门控 defer/release。OpenCode 侧已归档落地（`20260712113320-OpenCode展示排序接入`）。

Codex 侧 ordering 能力函数已存在，但**产品未接入对齐**：飞书/IM 等通道上，Codex 会话的工具开始/结束与进度消息顺序，与 Cursor/OpenCode 主引擎体验不一致，用户难以跟进当前进度。

本变更目标是把 Codex 展示排序接到与 OpenCode/Cursor **同一产品口径**，消除引擎间体感割裂。

## 二、用户可见症状

| 症状 | 典型表现 |
|------|----------|
| 顺序错乱 | Codex 会话卡片/通知中工具开始、结束、进度消息先后颠倒或交错 |
| 进度难跟 | 工具尚未结束时正文或其它消息抢先展示，用户误判进度 |
| 引擎割裂 | 同一产品内 Codex 与 Cursor/OpenCode 展示顺序不一致，切换引擎体感断裂 |
| 通道侧 | 飞书/IM 工具相关展示顺序与主引擎口径不一致 |

## 三、目标与非目标

### 目标（必须达成）

1. **口径对齐**：Codex 工具开始 / 结束 / 进度展示顺序与 OpenCode 已落地场景一致。
2. **无 Cursor 回归**：接入后 Cursor 侧既有展示排序行为不退化。
3. **通道一致**：飞书/IM 上 Codex 会话卡片/通知顺序与主引擎产品体验对齐（在既有模板能力内）。
4. **可验收**：对齐场景可对照 OpenCode 归档验收口径复现。

### 非目标（明确不做）

- **不改** 飞书卡片模板大改或视觉重做。
- **不重做** 四引擎 Presentation 总架构。
- **不做** 微信通道。
- **不在 propose 阶段** 绑定实现类名、文件路径、内部接口签名（归属 `/kb-design`）。

## 四、用户与场景

### 用户

- **IM / 飞书会话用户**：通过会话卡片与通知跟进 Codex 工具执行进度，期望顺序与 Cursor/OpenCode 一致。
- **多引擎用户**：在 Cursor / OpenCode / Codex 间切换时，期望展示排序口径统一。

### 场景

| 场景 | 简述 |
|------|------|
| **S1 工具过程排序** | Codex 多轮 tool 执行中，开始/结束/进度消息顺序与 OpenCode 同场景一致。 |
| **S2 进度可读** | 工具活跃期间不出现与 OpenCode 口径相悖的抢屏/乱序，用户可跟进度。 |
| **S3 飞书/IM 一致** | 飞书/IM 通道上 Codex 卡片/通知顺序与主引擎体验对齐（模板不大改）。 |
| **S4 Cursor 无回归** | 接入后 Cursor 既有排序场景行为不变。 |
| **S5 依赖可直接做** | OpenCode ordering 已落地，本变更无硬性阻塞依赖。 |

## 五、功能需求

| 编号 | 需求描述 |
|------|----------|
| R1 | **Codex 接入展示排序**：Codex 会话的工具开始/结束/进度展示顺序对齐 OpenCode/Cursor 产品口径。 |
| R2 | **对齐场景一致**：与 OpenCode 已验收的对齐场景在 Codex 上表现一致。 |
| R3 | **通道体验**：飞书/IM 上 Codex 相关展示顺序与主引擎一致（在既有模板内）。 |
| R4 | **无 Cursor 回归**：不改变 Cursor 既有展示排序行为。 |
| R5 | **范围克制**：不改飞书卡片模板大改；不重做四引擎 Presentation；不做微信。 |

## 六、验收标准

### 6.1 主路径

1. **顺序对齐**：Codex 工具开始 / 结束 / 进度展示顺序与 OpenCode 对齐场景一致。
2. **进度可读**：对齐场景下无与 OpenCode 口径相悖的乱序或抢屏，用户可跟进进度。
3. **飞书/IM**：Codex 会话卡片/通知顺序与主引擎体验一致（既有模板能力内）。

### 6.2 回归与边界

1. **Cursor 无回归**：Cursor 既有展示排序场景行为不变。
2. **非目标未扩大**：未引入飞书模板大改、四引擎 Presentation 重做、微信通道。

### 6.3 非功能

1. 变更代码含中文注释。
2. 不引入与展示排序无关的产品策略变更；须改策略时另开变更。

## 七、范围边界

### 在范围内

- Codex 展示排序与 OpenCode/Cursor 产品口径对齐。
- 飞书/IM 上 Codex 工具相关展示顺序对齐（既有模板内）。
- 对齐场景回归与 Cursor 无回归验收。

### 不在范围内

- 飞书卡片模板大改或视觉重做。
- 四引擎 Presentation 总架构重做。
- 微信通道。
- OpenCode ordering 本身的再设计（已落地，仅作对齐基线）。

## 八、风险与依赖

| 风险 / 依赖 | 说明 | 缓解方向 |
|-------------|------|----------|
| 依赖 OpenCode 口径 | OpenCode 展示排序已落地，为本变更对齐基线 | 依赖已满足，可直接做；对照归档验收场景 |
| 引擎语义差异 | Codex 事件流与 OpenCode 映射不完全同构 | design 阶段对齐产品口径，不臆造事件语义 |
| Cursor 回归 | 共用 Presentation 路径时误伤 Cursor | 验收硬门槛：Cursor 无回归 |
| 模板边界 | 误扩到飞书模板大改 | 非目标约束；模板只做顺序相关必要协作 |
