# MCP 展示迁移至 Agent 详情产品需求文档

> **变更 ID**：`20260630104251-MCP展示迁移至Agent详情`
> **来源**：kb-propose
> **类型**：enhancement（含界面重构）
> **优先级**：P2
> **外部 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无

## 背景

cursor-claw 已支持多种 Agent 执行引擎（Cursor SDK、Claude Agent SDK），后续还将扩展更多 SDK 类型（如 Codex SDK）。MCP（Model Context Protocol）服务是 Agent 运行时能力的重要组成部分，其实际生效范围与**具体工作区、具体运行中的 Agent 会话**强相关，而非全局静态配置。

当前产品将 MCP 服务器的列表、状态探测、增删改与工具预览集中放在**设置页**的 MCP Tab。管理员在设置中查看的是「配置文件层面的 MCP 清单」，难以对应「此刻某条活跃会话实际加载了哪些 MCP、状态如何」。主界面 Agent 卡片展开「活跃会话」后，仅展示排队消息，**无法查看该会话绑定的 MCP**。

随着多 SDK 并存，不同引擎对 MCP 的加载方式、状态表达与可操作项存在差异。将 MCP 展示迁移至**主界面 Agent / 活跃会话详情**，并按引擎类型区分展示策略，更符合「MCP 属于运行中 Agent」的产品心智，也为后续 SDK 扩展预留一致入口。

## 目标

1. 主界面 Agent 详情（活跃会话展开区域或等价详情入口）中，展示**该会话实际绑定**的 MCP 服务器列表及运行状态。
2. 按 Agent 执行引擎类型（Cursor SDK、Claude Agent SDK 等）采用**差异化展示与交互策略**，避免用单一 UI 假设覆盖所有引擎。
3. 自设置页**移除 MCP 服务器 Tab 及其中的列表/状态/管理类展示**，使 MCP 查看入口与运行中 Agent 绑定。
4. 产品口径上为未来新增引擎（如 Codex SDK）预留「按引擎类型扩展展示策略」的能力，不要求本变更一次性实现 Codex，但验收时需确认扩展点清晰。

## 非目标

- 不改变 MCP 配置文件（全局与项目级）的底层读写语义与 Agent 运行时注入逻辑本身；本变更聚焦**展示位置与交互**，非 MCP 加载机制重写。
- 不在本变更中新增或替换 MCP 协议实现、OAuth 流程内核或工具调用执行链路。
- 不改动 IM 通道连接、任务调度、工作流 YAML 定义。
- 不要求本变更完成 Codex SDK 的 MCP 展示实现（仅预留策略口径）。
- 后续实现须遵守工程约束：单一代码文件不超过 300 行，超限须拆分重构（属实现阶段约束，不影响本 PRD 验收口径）。

## 用户故事

**管理员 / 运维视角**：

- 作为管理员，我在主界面查看某 Agent 的活跃会话时，希望一眼看到该会话当前加载了哪些 MCP、是否在线/已授权/异常，以便排查工具不可用问题，而不必先到设置页对照全局列表猜测。
- 作为管理员，当同一应用内同时存在 Cursor SDK 与 Claude Agent SDK 会话时，我希望 MCP 详情按引擎类型呈现合理的信息粒度（例如状态字段、可执行操作），而不是两种引擎共用一套误导性按钮。
- 作为管理员，设置页不再出现 MCP 服务器大段管理 UI 后，我仍需要明确：若需修改 MCP 配置，应通过何种产品路径（见「待产品确认项」）。

**日常用户视角**：

- 作为桌面应用用户，我在 Dashboard 展开 Agent 活跃会话时，能查看与该会话相关的 MCP 状态摘要，理解当前 Agent 具备哪些外部工具能力。

## 功能需求

### F1：设置页移除 MCP 展示与管理入口

- 设置页不再提供独立的「MCP 服务器」Tab（或等价主导航入口）。
- 自设置页移除：MCP 列表、运行状态探测结果展示、增删改控件、工具列表预览、登录/授权类操作入口等**面向 MCP 服务器的管理型 UI**。
- **待产品确认**：是否完全禁止在设置内编辑 MCP 配置，或降级为「打开配置文件」等轻量入口（见文末待确认项）；本 PRD 默认验收口径为「设置页无 MCP 管理型展示」，具体编辑能力以产品确认为准。

### F2：主界面 Agent / 活跃会话详情展示 MCP

- 在主界面 Agent 卡片展开「活跃会话」（或等价 Agent 详情）区域，新增 MCP 相关区块。
- 展示内容至少包含：MCP 服务器名称、启用/禁用或连接状态、异常/需授权等状态提示（字段命名与图标以实现阶段为准，但需对用户可读）。
- 列表范围须绑定**该活跃会话**（含其工作区上下文），而非应用全局静态清单；无活跃会话或无 MCP 时展示明确空态文案。
- 与现有「排队消息」等同屏共存时，信息层级清晰，不挤占核心会话操作。

### F3：按引擎类型的展示策略

- 系统须识别会话所属 Agent 引擎类型（至少区分 Cursor SDK 与 Claude Agent SDK），并据此选择 MCP 展示策略。
- **Cursor SDK 会话**：展示该会话工作区上下文下实际生效的 MCP 列表与状态；可操作项（如刷新状态、查看工具、触发授权）应符合 Cursor 路径用户预期，且不与 Claude 路径混用文案。
- **Claude Agent SDK 会话**：展示该会话实际绑定的 MCP 列表与状态；展示字段与可操作项应符合 Claude Agent 路径预期（包括 Profile/工作区与 MCP 关系的合理说明或空态）。
- **扩展预留**：产品文档与界面结构须体现「引擎类型 → 展示策略」的可扩展性；未来 Codex SDK 接入时可在不推翻主界面入口的前提下新增策略，无需再次搬迁 MCP 入口。

### F4：状态刷新与一致性

- Agent 详情中的 MCP 状态应可随用户主动刷新或会话生命周期（启动、重连、结束）更新，避免长期展示过期状态。
- 同一会话在详情中看到的 MCP 列表，应与该会话 Run 实际使用的 MCP 集合一致（允许展示层延迟，但不得长期与运行事实相悖）。

### F5：与既有能力的衔接

- 迁移后，用户在 Agent 详情查看 MCP 时，不应丢失迁移前在设置页可获得的**关键诊断信息**（至少：有哪些 MCP、是否可用、是否需要授权）；具体信息粒度按 F3 分引擎交付。
- 若设置页完全移除 MCP 编辑能力，产品须提供可接受的替代路径说明（配置文件、外部编辑器或后续独立入口），并在界面或文档中可被用户发现（实现细节不在本 PRD 范围）。

## 验收标准

1. 打开设置页：不存在 MCP 服务器 Tab 或等价的 MCP 列表/状态/增删改/工具预览/登录管理主界面（与 F1 及待确认项最终决策一致）。
2. 主界面存在至少一条活跃 Cursor SDK 会话：展开 Agent / 会话详情可见 MCP 区块，列表对应该会话上下文，状态字段可读；刷新或会话重启后状态可更新。
3. 主界面存在至少一条活跃 Claude Agent SDK 会话：展开详情可见 MCP 区块，展示策略与 Cursor 会话存在合理差异（非简单复制同一套控件），且无引擎类型错绑。
4. 无 MCP 或未加载 MCP 的会话：展示明确空态，不出现设置页时代的全局列表误导。
5. Agent 详情中 MCP 信息与该会话实际工具能力一致：会话能调用的 MCP 在详情中可见；详情中标记不可用的 MCP 与用户感知一致（允许短暂延迟，不可长期矛盾）。
6. 回归：IM 消息触发 Run、任务执行、MCP 工具调用、会话排队展示等既有主流程不因入口迁移而退化。
7. 产品/设计评审确认：引擎类型扩展口径（含未来 Codex SDK）在 PRD 或设计说明中有明确占位，无需第三次搬迁 MCP 主入口。

## 待产品确认项

| 编号 | 议题 | 建议默认 | 影响 |
|------|------|----------|------|
| C1 | 设置页是否**完全移除** MCP 配置编辑能力 | 移除管理 UI；可选保留「打开 MCP 配置文件」外链 | 决定 F1 验收边界与 F5 替代路径 |
| C2 | Agent 详情中是否允许**授权/登录**类操作，还是仅只读展示 + 引导至外部配置 | 首版倾向只读 + 状态 + 刷新；授权操作按引擎分策略后续迭代 | 决定 F3 交互深度与首期范围 |
| C3 | MCP **工具列表**是否在 Agent 详情展开，还是仅展示服务器级状态 | 建议保留可折叠的工具列表（与迁移前设置页诊断能力对齐） | 决定详情信息密度 |
| C4 | 同一 Agent 多活跃会话时，MCP 区块是否**按会话逐条**展示 | 建议与会话条目绑定，每条会话独立 MCP 区块 | 决定 Dashboard 布局 |

## 风险与依赖

- 部分会话列表当前可能缺少工作区或引擎类型等展示所需元数据，实现阶段需补齐产品所需字段（属设计/实现议题，不影响本 PRD 目标陈述）。
- 设置页 MCP Tab 代码体量较大，迁移时需同步清理避免残留入口与双源真相。
- 多引擎策略若首期只做「最小差异」，需在产品确认 C2/C3 后明确首期与后续迭代边界，避免验收争议。
