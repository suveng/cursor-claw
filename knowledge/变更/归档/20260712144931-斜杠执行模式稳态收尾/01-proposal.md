## 一、背景与问题陈述

父变更「控制层HTTP化与斜杠去Electron依赖」已把斜杠主路径迁到 Daemon 作为控制面单一事实来源（SSOT），但**运维默认与文档稳态尚未收口**：

- 默认斜杠执行模式仍为 **dual（双路径）**，而非仅 Daemon。
- 迁移期 **poll / 本地命令落盘双写** 仍在，行为难预测，存在重复执行风险。
- 产品债 **T10** 相关的旧管理入口（如 `/mcp-admin` 一类）**废弃未收尾**；健康检查 / MCP 管理仍可能残留旧入口观感。

运维与产品尚未进入「**仅 daemon**」稳态：文档说 SSOT 在 Daemon，默认与现场行为仍是迁移期双写。

**依赖说明**：宜在「HTTP dispatch失败重入队对齐」之后推进，或可并行（**无硬代码依赖**，同属控制面稳态收尾）。

## 二、用户可见症状

| 症状 | 典型表现 |
|------|----------|
| 路径不唯一 | 斜杠 / 菜单指令可能同时或先后经双路径执行，结果时序与落点难预期 |
| 重复执行风险 | 同一指令在双写窗口内可能被处理两次（或一次有效一次无效），用户看到重复动作或重复回复 |
| 默认非稳态 | 新装 / 重启后默认仍是 dual，而非「仅 Daemon」运维预期 |
| 旧入口残留 | 健康 / MCP admin 仍可能出现旧入口或废弃未说明的管理路径 |
| 文档与默认不一致 | 对外宣称 Daemon 为 SSOT，现场默认与双写行为仍像迁移期 |

## 三、目标与非目标

### 目标（必须达成）

1. **默认稳态**：默认斜杠执行模式切到 **daemon**，日常运维无需再依赖 dual 才能「基本可用」。
2. **双写收口**：废弃或文档化关闭 dual / Electron 侧双写；若保留兼容，须明确为**可选兼容**而非默认。
3. **旧入口结论**：对 T10 类旧管理入口（含 `/mcp-admin` 等）给出明确的**废弃或移除**产品结论，并落到可运维说明。
4. **poll 去重路径**：迁移期 poll 去重 / 兼容路径可**整段退役**，或明确标注「仅兼容、非默认」；不得与默认 daemon 路径并存为双写主路径。
5. **无双写重复执行**：在默认配置下，同一斜杠指令不得因双路径导致重复执行。

### 非目标（明确不做）

- **不重做** 斜杠功能集（指令清单、能力范围以现网为准）。
- **不改** IM 通道（飞书等接入与消息形态）。
- **不引入** 新的斜杠指令语法或用户侧新写法。
- **不在 propose 阶段** 绑定实现类名、文件路径、内部接口签名（归属 `/kb-design`）。

## 四、用户与场景

### 用户

- **日常用户**：发斜杠 / 点菜单，期望稳定一次执行、结果可预期。
- **运维**：期望默认即「仅 Daemon」稳态；兼容模式需有文档与显式开关，而非静默双写。
- **MCP / 健康管理使用者**：期望管理入口唯一、废弃入口有明确说明或不可达。

### 场景

| 场景 | 简述 |
|------|------|
| **S1 默认 daemon 可用** | 默认配置下，斜杠经 Daemon 完成；无需打开 dual 才能用。 |
| **S2 关闭双写** | 默认下无 poll / 本地落盘与 Daemon 的双写主路径；无重复执行。 |
| **S3 dual 可选兼容** | 若保留 dual，须显式开启且有运维文档；关闭后行为回到仅 daemon。 |
| **S4 旧 admin 入口** | `/mcp-admin` 等旧入口已废弃移除，或文档标明废弃且产品路径指向新入口。 |
| **S5 Electron 未就绪** | 桌面端未就绪时，默认 daemon 路径仍可完成斜杠（不回退为静默依赖双写）。 |

## 五、功能需求

| 编号 | 需求描述 |
|------|----------|
| R1 | **默认 daemon**：产品/运维默认斜杠执行模式为 daemon，开箱即可进入稳态。 |
| R2 | **dual 非默认**：dual 不得作为默认；若保留，须为可选兼容并有文档说明如何开启/关闭。 |
| R3 | **双写关闭或仅兼容**：poll / 本地命令落盘双写不得作为默认主路径；退役或明确仅兼容。 |
| R4 | **无重复执行**：默认配置下同一指令不得因双路径重复执行。 |
| R5 | **旧管理入口结论**：T10 相关旧入口（含 `/mcp-admin` 类）须有废弃或移除的明确结论，并消除「双入口并存且无说明」的用户观感。 |
| R6 | **文档与默认一致**：运维/产品说明中的默认模式与现场默认行为一致，均为「仅 daemon」稳态。 |
| R7 | **与父变更划界**：父变更完成控制面 HTTP 化与斜杠去 Electron 依赖；本变更专责**默认与双写收口、旧入口收尾**，不重开斜杠功能集。 |

## 六、验收标准

### 6.1 主路径

1. **默认 daemon 可运行**：默认配置下斜杠指令可经 Daemon 完成，无需 dual。
2. **无双写重复执行**：默认下人为连发 / 单次指令，不得出现因双路径导致的重复执行。
3. **dual 可选且有文档**：若仍提供 dual，须非默认、可显式开关，并有运维文档；关闭后回到仅 daemon。
4. **旧 admin 入口有结论**：`/mcp-admin` 类旧入口已移除，或文档标明废弃且不可再被误用为正式入口。

### 6.2 边界

1. 斜杠功能集、IM 通道、指令语法不因本变更而改变用户侧能力集合。
2. 不要求改 IM 卡片视觉。

### 6.3 非功能

1. 默认与文档一致，降低运维误配与排障成本。
2. 工程规范：变更代码含中文注释；单文件不超过 300 行（超限须拆分，属实现阶段约束）。

## 七、范围边界

### 在范围内

- 默认斜杠执行模式切到 daemon。
- dual / Electron 双写的废弃或「仅兼容」文档化与默认关闭。
- T10 旧管理入口（含 `/mcp-admin` 类）的废弃/移除结论与用户可见收尾。
- poll 去重 / 迁移兼容路径的退役或「仅兼容」界定。
- 默认下消除双写重复执行。

### 不在范围内

- 重做或扩展斜杠功能集。
- 改 IM 通道接入与消息形态。
- 新指令语法或用户侧新写法。
- HTTP dispatch 失败重入队策略（属相邻变更「HTTP dispatch失败重入队对齐」）。

## 八、风险与依赖

| 风险 / 依赖 | 说明 | 缓解方向 |
|-------------|------|----------|
| 相邻控制面变更 | 与「HTTP dispatch失败重入队对齐」同属控制面稳态；无硬代码依赖但宜先后或并行协调 | 依赖说明写入背景；设计阶段划界 |
| 兼容回退需求 | 部分环境仍依赖 dual | dual 仅可选兼容 + 文档；默认仍为 daemon |
| 旧入口误用 | 废弃不彻底导致双入口 | 验收强制「有明确废弃/移除结论」 |
| 重复执行回归 | 收口不彻底仍双写 | 验收强制默认无双写重复执行 |

| 文档 | 影响 |
|------|------|
| Daemon / 斜杠控制面（默认执行模式、双写说明） | 高：默认与稳态口径须更新 |
| 父变更归档「控制层HTTP化与斜杠去Electron依赖」限制/TODO | 中：标明双写与 T10 收尾由本变更清偿 |
