## 4、场景摘要

### 4.1 环境与前置

| 项 | 要求 |
|----|------|
| 应用 | Cursor Claw 已启动，Daemon **运行中**（`/status` 可正常回复） |
| 通道 | 飞书群已绑定；发送者为**授权用户** |
| 构建 | 含本变更的 dev 或打包版本（`command-executor.ts` 等已编译） |
| 环境变量 | **默认用例**：不设置或 `SLASH_EXEC_MODE=daemon`；**dual 用例**：显式 `SLASH_EXEC_MODE=dual` 后重启应用 |
| 队列（可选） | 可先 enqueue 1～2 条待处理消息，便于观察「已清空 N 条队列消息」文案 |
| 凭据 | **勿**写入本文；飞书凭据以本地「已配置」为准 |

### 4.2 实机验收清单（用户可执行）

| ID | 场景 | 前置条件 | 操作步骤 | 预期结果 |
|----|------|----------|----------|----------|
| **R1** | 成功路径（稳态 daemon） | Daemon 运行；默认或未设 `SLASH_EXEC_MODE` | ① 飞书群发送 `/restart`<br>② 等待 **3–5s**（daemon stop→start 约 1.5s + 余量）<br>③ 统计群消息条数与文案 | 收到**一条**终态消息，文案含 **`✅ Daemon 重启成功`** 及 **`已清空 N 条队列消息`**（N≥0）<br>**不应**再出现单独的「正在重启...」或重复成功/失败消息<br>重启后 `/status` 仍可用 |
| **R2** | Poll/dual 模式 | 设置 `SLASH_EXEC_MODE=dual` 并**重启应用**；Daemon + Electron poll 均运行 | 同 R1：群发送 `/restart` → 等待 3–5s | 终态消息**能送达**（含 `✅ Daemon 重启成功`）<br>验证 poll 路径 `readLockFile()?.port` 刷新后 `/cmd/result` 未因旧 port 静默失败 |
| **R3** | 失败路径（**可选**，可跳过） | 若难以安全模拟 `startDaemon` 失败 | **观察项**：人为制造 daemon 启动失败（如占用端口）后发送 `/restart`；或仅查 UI 日志 | 群消息含 **`❌ Daemon 重启失败:`** + 错误摘要 + 清空队列说明<br>UI 日志有 **`[指令] Daemon 重启失败:`**（`broadcastLog` ERROR）<br>仍仅**一条**终态群消息 |
| **R4** | 回归：其它斜杠 | R1 或 R2 通过后 | 依次发送 `/status`、`/stop`（或 `/help`） | 各指令正常回复，无异常静默、无 `failedCooldowns` 类报错<br>`/restart` 不再因前序 hotfix 未定义变量中断 |

### 4.3 失败判责

| 现象 | 优先怀疑 |
|------|----------|
| 重启后无任何群消息 | poll 旧 port / HTTP sink 未捕获；查 UI 日志「指令结果回报失败」 |
| 收到多条消息或「正在重启...」 | 中间态提前 `reply` 回归；确认仅 `restartDaemon()` 完成后 reply |
| dual 模式下消息丢失 | `SLASH_EXEC_MODE` 未生效或 Electron poll 未运行 |
| 文案无清空条数 | 队列为空时 N=0 仍应出现「已清空 0 条」 |
