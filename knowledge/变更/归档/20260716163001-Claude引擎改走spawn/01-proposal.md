## 一、背景与问题

Claude Code 通道当前仍以 SDK `query()` 为主执行路径。产品侧已确认的痛点包括：

1. **冷启动慢**：新会话/新任务进入可用状态的等待偏长，体感差。
2. **状态不黏**：会话侧依赖（如 MCP 等）易出现每次重传、上下文难延续等问题，用户侧表现为重复配置或能力不稳定。
3. **中断与排障可控性差**：中断、观察失败原因、对照 CLI 行为时缺少清晰抓手，排障偏黑盒。
4. **绑定 SDK 版本**：能力与排障路径受 SDK 封装牵制，升级与问题定位成本高。

用户明确要求：**Claude 引擎不再以 SDK `query()` 为主路径**，改为 **spawn Claude Code CLI**（或文档中的等价 spawn 能力）。具体实现选型（CLI 进程形态、与 SDK spawn 封装的取舍等）留给 `/kb-design`；本 PRD 只锁定产品目标与验收。

## 二、目标与非目标

### （一）本期目标

1. **Claude 通道主路径改 spawn**：用户通过 Claude 引擎发起的会话/任务，默认走 spawn 主路径，而不再默认走 `query()` 主路径。
2. **可感知体验改善**：相对现网 query 主路径，冷启动等待与中断/失败时的可控性、可诊断性有用户可感知的改善（不必在本阶段锁死毫秒数或具体日志字段）。
3. **失败可降级或可诊断**：spawn 主路径失败时，产品侧须有明确降级策略或可理解的失败反馈，避免「无声卡死」或无法排查。
4. **引擎隔离**：仅改变 Claude 引擎行为；Cursor / Codex / OpenCode 等其它引擎不因本变更改路径、不回归。

## 三、方案说明（产品口径）

### 主路径切换

- 用户选择 Claude 通道并发起会话/任务后，**默认执行路径为 spawn**（产品表述：拉起 Claude Code CLI 进程，或文档所述等价 spawn 能力）。
- 不再把 SDK `query()` 作为 Claude 引擎的**默认主路径**。
- 是否保留 query 作为降级后备、如何暴露失败信息：产品要求「失败可降级或可诊断」，细节由 design 落地。

### 体验期望（相对现网 query）

- **冷启动**：进入可交互/可处理状态的等待应有可感知改善。
- **状态延续**：减少「每次会话像全新冷环境」带来的 MCP 等依赖重复准备感（产品期望；实现机制归 design）。
- **中断与排障**：用户或运维能更清晰地感知中断结果与失败原因，降低黑盒感。

### 与其它引擎

- Cursor / Codex / OpenCode 保持现网路径与行为；验收须覆盖「其它引擎不受影响」。

## 四、用户故事与验收标准

### 用户故事

- **Claude 通道用户**：发起新会话或任务后，走 spawn 主路径完成对话/执行；相对旧 query 主路径，冷启动与可控性有改善。
- **中断/失败场景用户**：任务失败或需中断时，能得到可理解反馈或可继续的降级路径，而非无声失败。
- **多引擎用户**：使用 Cursor / Codex / OpenCode 时行为与现网一致，不因 Claude 改路径被连带影响。
- **排障角色**：能对照 Claude Code CLI 行为或等价诊断信息定位问题，降低纯 SDK 黑盒依赖。

### 验收标准（产品可验收）

1. **主路径为 spawn**：Claude 通道会话/任务默认走 spawn 主路径（可观测为进程/CLI 形态或产品约定的 spawn 证据；不以继续默认走 query 为合格）。
2. **冷启动可感知改善**：相对同环境现网 query 主路径基线，冷启动等待有可说明的改善（对比方法在 design/测试阶段固定；propose 不锁死毫秒数）。
3. **可控性/可诊断改善**：中断或失败时，用户侧或运维侧能获得明确结果或可诊断信息；不得长期无反馈卡死。
4. **失败可降级或可诊断**：spawn 主路径不可用时，有产品级降级或明确失败提示（具体策略归 design，本条验收「有策略且可演示」）。
5. **其它引擎不受影响**：Cursor / Codex / OpenCode 在同等冒烟场景下行为不回归。

## 五、影响范围（产品/知识）

- **用户可见**：Claude 通道启动方式、冷启动体感、中断/失败反馈与排障可理解性。
- **知识域**：Agent 调度 / Claude 执行引擎相关说明中，「主路径为 query」类表述需在后续 design/archive 由知识库流程更新；本阶段只记影响，不改业务域正文。
- **不在本期**：其它引擎路径、预热变更实现并入、UI/视觉、外部工单登记（本仓无 integrations）。

## 七、风险与待确认

1. **与预热变更并存**：本轮不自动取消 `20260714000128`；若两边并行推进 design/实现，可能双主方向冲突。**待用户确认**是否搁置/取消预热变更。
2. **降级策略产品口径**：失败时「自动回退 query」还是「仅报错可诊断」——本 PRD 允许二者之一或组合，**design 前建议用户点选偏好**（非阻断 propose 落盘）。
3. **CLI 可用性前提**：spawn 依赖本机/运行环境具备可用的 Claude Code CLI（或等价能力）；环境缺失时的产品提示文案需在 design 明确。
4. **验收基线**：冷启动对比需约定同机、同模型、新会话口径；数值阈值在测试阶段再定。
