# 多引擎MCP设置实质化产品需求文档

> **变更 ID**：`20260712145827-多引擎MCP设置实质化`
> **来源**：kb-propose
> **类型**：功能
> **优先级**：P2
> **外部 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无
> **依赖**：宜在「斜杠执行模式稳态收尾」之后（admin HTTP 收口后再做设置页）

## 一、背景与问题陈述

桌面 Settings 里 **Codex / OpenCode** 等非 Cursor 引擎的 MCP 配置多为**占位**：用户难以在产品内完成真实配置或看清状态，上手成本高。

同时：

- 用户往往仍须**自行**把 Cursor MCP 指到 Daemon，缺少可复制的一站式指引，步骤摩擦大。
- `/mcp` 健康列依赖 Electron agent-api；**未就绪时显示「未知」**，状态不透明，易被理解为故障或未配置。
- 斜杠控制层 HTTP 化后，admin 能力已部分走 HTTP，但**多引擎设置体验仍断层**——控制面可用，设置页仍像迁移期占位。

本变更专责把多引擎 MCP 设置从「占位/静默未知」收成**可操作或明确不支持**，并补齐健康降级文案与可复制指引。

## 二、用户可见症状

| 症状 | 典型表现 |
|------|----------|
| Settings 占位 | Codex / OpenCode（及必要处）MCP 区无法真实配置或只显示占位说明 |
| 健康「未知」 | agent-api 未就绪时健康列静默为「未知」，无原因说明 |
| 手工改 MCP | 须自行改 Cursor MCP 指向 Daemon，产品内无清晰可复制指引 |
| 体验断层 | admin 侧已部分 HTTP 化，设置页仍像未收尾的占位页 |

## 三、目标与非目标

### 目标（必须达成）

1. **可真实配置或明确不支持**：Codex / OpenCode（及产品判定必要的引擎）在 Settings 中 MCP 设置可真实配置/展示；若某引擎确不支持，须**明确标注「不支持」**，不得继续静默占位。
2. **健康状态可理解降级**：在 agent-api 未就绪等依赖不可用时，健康展示须有**明确降级文案**（说明暂不可查/依赖未就绪），禁止静默「未知」。
3. **减少手工改 MCP 摩擦**：减少「请自行改 Cursor MCP」步骤，或提供**可复制**的配置指引（路径/片段），使用户能按指引一次完成指向 Daemon。
4. **文档与 UI 一致**：运维/产品说明与 Settings 实际能力、健康文案一致。

### 非目标（明确不做）

- **不重做**整页 Settings（布局、信息架构沿用现有）。
- **不改** Daemon MCP 协议本体。
- **不做**微信相关能力。
- **不在 propose 阶段**绑定实现类名、文件路径、内部接口签名（归属 `/kb-design`）。

## 四、用户与场景

### 用户

- **多引擎使用者**：在 Settings 配置 Codex / OpenCode 等引擎的 MCP，期望可操作、状态可读。
- **运维 / 排障**：健康检查失败或未就绪时，期望文案说明原因，而非「未知」。
- **首次对接 Daemon MCP 的用户**：期望产品内可复制指引，少查外部文档、少猜配置路径。

### 场景

| 场景 | 简述 |
|------|------|
| **S1 可配置引擎** | 支持 MCP 设置的引擎：可在 Settings 完成配置/展示，非占位。 |
| **S2 明确不支持** | 不支持 MCP 设置的引擎：UI 明确「不支持」，无静默占位。 |
| **S3 健康降级** | agent-api 未就绪：健康列显示明确降级文案，不显示静默「未知」。 |
| **S4 可复制指引** | 需指向 Daemon 的 MCP 配置：产品提供可复制指引，减少手工摸索。 |
| **S5 与 admin HTTP 收口后衔接** | 「斜杠执行模式稳态收尾」后，设置页与健康/admin 入口体验一致、无双入口困惑。 |

## 五、功能需求

| 编号 | 需求描述 |
|------|----------|
| R1 | Codex / OpenCode（及必要处）MCP 设置从占位改为可真实配置/展示，或明确「不支持」。 |
| R2 | 健康状态在 agent-api 等依赖未就绪时，展示明确降级文案，禁止静默「未知」。 |
| R3 | 提供可复制的 Cursor→Daemon MCP 指引，或减少须自行改配置的步骤。 |
| R4 | Settings 仅实质化相关区段，不重做整页布局。 |
| R5 | 文档/帮助文案与 UI 能力、健康降级语义一致。 |
| R6 | 不改 Daemon MCP 协议本体；不做微信。 |

## 六、验收标准

### 6.1 主路径

1. **占位消除**：相关引擎 MCP 区为可操作配置/展示，或明确「不支持」——不得保留无说明的静默占位。
2. **健康非静默未知**：agent-api 未就绪时，健康展示含明确降级文案（可读原因），不得仅显示「未知」。
3. **指引可用**：用户可按产品内指引（含可复制内容）完成指向 Daemon 的 MCP 配置，或确认已无需手工改配置。
4. **文档/UI 一致**：对外说明与 Settings、健康文案无矛盾。

### 6.2 边界

1. Settings 整体布局不因本变更重做。
2. Daemon MCP 协议行为与既有约定不变。
3. 不引入微信相关能力。

### 6.3 非功能

1. 上手与排障成本下降：状态可读、指引可复制。
2. 工程规范：变更代码含中文注释；单文件不超过 300 行（超限须拆分，属实现阶段约束）。

## 七、范围边界

### 在范围内

- Codex / OpenCode（及必要处）Settings MCP 设置实质化或明确不支持。
- 健康状态在依赖未就绪时的降级文案。
- Cursor→Daemon MCP 可复制指引或等价减少手工步骤。
- 文档与 UI 口径对齐。

### 不在范围内

- 整页 Settings 重做或视觉改版。
- Daemon MCP 协议本体改造。
- 微信能力。
- 斜杠执行模式默认/双写收口（属「斜杠执行模式稳态收尾」）。

## 八、风险与依赖

| 风险 / 依赖 | 说明 | 缓解方向 |
|-------------|------|----------|
| 依赖稳态收尾 | 宜在「斜杠执行模式稳态收尾」之后，admin HTTP 收口后再做设置页 | 依赖写入头部；设计阶段对齐入口 |
| 引擎能力差异 | 部分引擎可能无法对等配置 | 允许明确「不支持」，禁止静默占位 |
| 文案歧义 | 降级文案若含糊仍像故障 | 验收强制「可读原因」，非仅「未知」 |
| 指引过期 | 可复制指引与实际 Daemon 接入方式漂移 | 文档/UI 同轮对齐；archive 回写知识库 |

## 九、知识库影响初评

| 文档 | 影响 |
|------|------|
| Electron 桌面 / Settings 多引擎配置 | 高：MCP 设置能力与文案须更新 |
| MCP / 健康检查说明 | 高：降级语义与「未知」口径 |
| Daemon MCP 对接指引 | 中：可复制指引与指向 Daemon 步骤 |
| 斜杠 admin / 执行模式稳态相关说明 | 低～中：入口衔接，不重复收口范围 |

初评结论：本变更为**多引擎 MCP 设置体验实质化**；知识库以 Settings 能力、健康降级与对接指引为主，细节在 `/kb-design` 与 archive 定稿。
