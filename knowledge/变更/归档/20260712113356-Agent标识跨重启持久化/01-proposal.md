# Agent标识跨重启持久化产品需求文档

> **变更 ID**：`20260712113356-Agent标识跨重启持久化`
> **来源**：kb-propose
> **类型**：建议「可靠性」（待闸门确认）
> **优先级**：建议 P2（待闸门确认）
> **外部 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无

## 一、背景与问题

产品债 **T11**：Daemon 会话键→Agent 标识映射未跨重启持久化。重启后续聊、dispatch 路由依赖内存，用户感到「认不出是谁」、工作区可能漂移，与「Daemon 重启恢复调度态」方向未闭环。可选 P2，仍须 propose 排期。

## 二、用户可见症状

- Daemon 重启后续聊像新会话
- 同 chat 可能绑定不同 workspace
- 运维不敢重启 Daemon
- 与主进程 recover 能力割裂

## 三、目标与非目标

**目标**：重启后映射可恢复；dispatch/续聊路由一致；过期/失败可理解降级；范围限调度态 SSOT。

**非目标**：不改 IM 通道与卡片；不做全量会话库；不替代非 Cursor recover；不做回退栈 T4。

## 四、用户与场景

仅 Daemon 重启后续聊；标识与工作区恢复；TTL 清理旧映射；损坏文件降级 launch；与 Run recover 协同不冲突。

## 五、功能需求

| 编号 | 需求 |
|------|------|
| R1 | 映射变更时写盘 |
| R2 | Daemon 启动加载恢复路由 |
| R3 | TTL/清理防无限增长 |
| R4 | 加载失败可观测、用户可理解降级 |
| R5 | 不改 IM 协议 |

## 六、验收标准

1. 仅重启 Daemon 后同 chat 仍路由原 Agent 与工作区
2. 无静默换 workspace
3. 持久化损坏时降级且可理解提示
4. TTL 过期后不误用旧映射
5. 不涉及 IM 改造与全量会话库

## 七、范围边界

**在范围**：Daemon 调度态持久化与恢复。**不在范围**：IM、全量 DB、合并卡、回退栈 T4。

## 八、风险与依赖

- 可选 P2，排在控制面/续接之后
- 与 S7 recover 须约定顺序
- 脏映射可能导致错误目录
- 写盘须原子或恢复策略

## 九、知识库影响初评

多会话模型 T11（高）；Daemon 概览（中）；进程模型（中）；会话路由 T4 划界（低）。
