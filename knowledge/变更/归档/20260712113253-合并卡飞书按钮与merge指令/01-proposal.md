# 合并卡飞书按钮与merge指令产品需求文档

> **变更 ID**：`20260712113253-合并卡飞书按钮与merge指令`
> **来源**：kb-propose
> **类型**：建议「功能增强」（待闸门确认）
> **优先级**：建议 P1（待闸门确认）
> **外部 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无

## 一、背景与问题

飞书合并卡 MVP 已支持批次收集、静默窗口与回复编辑，但卡片「立即发送」「拆开」「编辑」等按钮回调未接线（产品债 **T8**）。用户无法点按完成合并控制，只能等静默或回复编辑。同时缺少 `/merge` 斜杠 fallback，按钮不可用时无等价文本入口。

## 二、用户可见症状

- 合并卡按钮点击无效果或无法完成预期动作
- 想立刻发送只能等静默窗口
- 无 `/merge` 等斜杠兜底
- 后端合并控制能力已有，飞书交互未闭环

## 三、目标与非目标

**目标**：飞书合并卡按钮可用；`/merge` 斜杠与按钮语义等价；与现有合并批次、Presentation 协同；操作结果可感知。

**非目标**：不重写 MergeBatch 状态机；不改 R3 重入队；不改微信与卡片视觉；不写技术实现细节。

## 四、用户与场景

主用户私聊连发合并后点「立即发送」；拆开批次；编辑后发送；按钮失败时用 `/merge` 兜底；未达合并阈值时单条路径不变。

## 五、功能需求

| 编号 | 需求 |
|------|------|
| R1 | 合并卡按钮接线：立即发送、拆开、编辑 |
| R2 | `/merge` 斜杠与按钮语义等价 |
| R3 | 非法状态返回可理解提示 |
| R4 | 成功路径不重复投递、不破坏流式首屏协调 |
| R5 | 待 dispatch ack 语义稳定后接线，避免 claim 冲突 |

## 六、验收标准

1. 主用户私聊合并卡「立即发送」可投递且可感知结果
2. 拆开、编辑在合法状态下可用
3. `/merge` 可完成发送、拆开等核心动作
4. 无批次或已结束时给出明确提示
5. 单条路径无回归

## 七、范围边界

**在范围**：飞书按钮回调、`/merge` 斜杠、合并控制用户入口。**不在范围**：状态机重写、队列 ack、微信、视觉改版。

## 八、风险与依赖

- **依赖**「dispatch失败重入队与ack策略」语义稳定后再接线
- **与 T10** 共享 Daemon 控制面，须划界
- **风险**：按钮与斜杠双入口防重复投递

## 九、知识库影响初评

Daemon 概览 T8（高）；消息桥接·飞书通道（中）；消息队列与路由（低）。
