# 工作流恢复入口与信号接口产品需求文档

> **变更 ID**：`20260712113344-工作流恢复入口与信号接口`
> **来源**：kb-propose
> **类型**：建议「功能增强」（待闸门确认）
> **优先级**：建议 P2（待闸门确认）
> **外部 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无

## 一、背景与问题

工作流支持 `paused` 与 `resumeWorkflow`，但无用户恢复入口：设置页无 UI，飞书 `/workflow` 无 resume。设计中的工作流信号 HTTP 未实现，paused 成为死胡同，外部集成无法闭环。

## 二、用户可见症状

- paused 后无法从产品入口继续
- 仅 Admin MCP 可恢复
- 外部系统无法注入继续信号
- 状态机图有 paused→running，入口缺失

## 三、目标与非目标

**目标**：paused 恢复入口（设置页和/或飞书指令）；实现工作流信号 HTTP；成功/失败可感知；与现有 `/workflow` 风格一致。

**非目标**：不做分支 Gateway；不重写引擎；不新增定义 create/update UI；不改队列。

## 四、用户与场景

设置页或飞书恢复 paused；`/workflow` resume；HTTP 信号注入；非法恢复报错；成功按 notifyChatId 通知。

## 五、功能需求

| 编号 | 需求 |
|------|------|
| R1 | 至少一个用户可见 paused 恢复入口 |
| R2 | `/workflow` 扩展 resume（或等价） |
| R3 | 工作流信号 HTTP 与设计契约对齐 |
| R4 | UI/指令/信号共享 resume 语义 |
| R5 | 授权与错误与现网管理一致 |

## 六、验收标准

1. paused 实例经产品入口恢复并继续执行
2. 授权下 resume 可用，未授权拒绝
3. HTTP 信号对合法 paused 实例可恢复
4. 非 paused 恢复返回可理解错误
5. 无分支 Gateway；队列无回归

## 七、范围边界

**在范围**：resume 入口、信号 HTTP。**不在范围**：Gateway、定义 CRUD UI、引擎重写。

## 八、风险与依赖

- 排在可靠性/控制面之后，相对独立
- 斜杠 HTTP 化未完成时须明确路径
- UI 与 HTTP 双入口须幂等
- 信号 HTTP 须授权防滥用

## 九、知识库影响初评

工作流·触发与管理（高）；工作流·概览（高）；节点执行（中）；Daemon HTTP（中）。
