# 远程指令全员与群聊开放产品需求文档

> **来源**：kb-propose
> **类型**：行为变更
> **优先级**：P1
> **外部 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无

## 一、背景与问题

cursor-claw 支持用户通过飞书（及微信）发送斜杠指令，远程查询状态、控制会话、切换工作区与模型、管理任务与工作流等。近期已上线飞书私聊自定义菜单，将常用指令以点击方式触达，降低记忆成本。

当前指令可用范围按**角色二分**：

| 角色 | 可用指令（现状） |
|------|------------------|
| **普通用户**（非主用户/非管理员） | `/help`、`/status`、`/reset`、`/stop`（本会话） |
| **管理员**（主用户） | 上述全部，另含 `/list`、`/clean`、`/restart`、`/workspace`、`/model`、`/mcp`、`/task`、`/workflow`、`/chat` 等 |

此外，**触达场景**也存在差异：

- **飞书私聊**：普通用户仅能通过文本或「基础指令」菜单使用上述四类指令；「管理员指令」菜单分组对非管理员不可见或点击后提示无权限。
- **飞书群聊**：用户须 @ 机器人后发送消息；即便通道已开启「允许他人使用」，普通用户在群聊中发送管理员级斜杠指令仍会被拒绝。
- **微信通道**：斜杠指令同样受管理员/普通用户二分约束（若通道已启用）。

产品方提出明确诉求：**所有命令不区分角色，均可使用；无论是在群聊还是私聊**。即取消「管理员专属指令」与「群聊不可用管理员指令」的产品限制，使任意已授权使用机器人的用户，在私聊与群聊中均可触达完整指令集（在通道准入策略允许的前提下）。

### 现状 vs 目标（产品维度）

| 维度 | 现状 | 目标 |
|------|------|------|
| 指令权限 | 管理员与普通用户二分，约十余条指令仅管理员可用 | **不区分角色**，全部指令对任意用户开放 |
| 飞书私聊 | 菜单分「基础 / 管理员」；非管理员无法成功执行管理类菜单 | 菜单与文本路径一致，**无管理员专属限制** |
| 飞书群聊 | 群聊可对话，但管理类斜杠指令对非管理员拒绝 | 群聊与私聊**指令集合一致**，不因场景降级 |
| 帮助与发现 | `/help`、进入私聊帮助卡、菜单文案标注「管理员」 | 文案与可见性**不再强调角色门槛** |

## 二、目标

1. **指令权限扁平化**：已接入通道内，凡系统支持的斜杠指令（及与之等价的菜单点击），**任意用户**均可发起并成功执行，不再因「非管理员」被拒绝。
2. **场景一致**：飞书**私聊与群聊**、文本斜杠与菜单点击，在「哪些指令可用」上**语义一致**；不因会话类型单独收窄指令集。
3. **触达面同步更新**：`/help`、进入私聊帮助卡片、飞书私聊自定义菜单等**用户可见说明**，不再将部分指令标注为「仅管理员」或隐藏管理员分组（具体菜单结构是否合并分组可在设计阶段定稿，但**不得**再因角色阻止执行）。
4. **与通道准入解耦**：本变更调整的是**指令级权限**；通道级「是否响应某用户/某群」（如仅主用户、是否允许他人使用等）**不在本期强行改写**，但须在风险节明确边界，避免用户误以为「开放指令 = 开放通道」。

## 三、用户故事与使用场景

### 3.1 群聊成员切换工作区

作为飞书群聊中的普通成员（非主用户），通道已允许他人 @ 机器人对话。我希望在群聊中发送 `/workspace` 查看或切换当前会话工作目录，而不被提示「仅管理员可用」，以便在协作场景下自行调整上下文。

### 3.2 私聊用户通过菜单新建临时会话

作为飞书私聊中的普通用户，我点击私聊菜单中的「新建临时会话」（或等价入口），期望与管理员点击后**相同行为**——成功创建临时会话并收到确认，而非无权限提示。

### 3.3 普通用户清理队列或重启服务

作为被授权使用机器人的用户，当会话堆积或需要重启后台时，我希望可以使用 `/list`、`/clean`、`/restart` 等运维向指令自行处理，而不必每次都找主用户代操作。

### 3.4 普通用户配置模型与 MCP

作为日常使用者，我希望通过 `/model`、`/mcp` 查看或调整当前会话可用的模型与工具配置，权限与主用户一致；若存在安全风险，产品应通过**明确规则或二次确认**解决，而非一刀切禁止非管理员。

### 3.5 群聊与私聊体验一致

作为用户，我在群聊 @ 机器人与在私聊中对话时，**同一套斜杠指令**均应可用；我不应记忆「这条指令只能私聊用」或「群聊只能查状态」。

### 3.6 帮助与菜单不再误导

作为新用户，我阅读 `/help`、进入私聊帮助卡或查看菜单时，不应看到「以下仅管理员可用」类表述；所列指令即**我实际能用的指令**。

## 四、功能需求

### 4.1 指令权限

| 编号 | 需求描述 |
|------|----------|
| F1.1 | **取消管理员专属限制**：原仅管理员可用的指令（包括但不限于 `/list`、`/clean`、`/restart`、`/workspace`、`/model`、`/mcp`、`/task`、`/workflow`、`/chat` 及其子命令）对**任意已授权用户**开放 |
| F1.2 | 原普通用户可用的指令（`/help`、`/status`、`/reset`、`/stop`）**保持可用**，行为按本节 F1.4 及「风险与待确认」定稿 |
| F1.3 | 用户发送指令时，系统**不得**再因「非主用户 / 非管理员」 alone 而拒绝；拒绝理由仅可为：指令不存在、参数不合法、通道未授权、会话上下文不满足等**与角色无关**的原因 |
| F1.4 | `/stop` 的停止范围（停全部运行中任务 vs 仅停当前会话）须在实现前由产品确认；定稿后对所有用户**同一规则**，见「七、风险与待确认」 |

### 4.2 场景覆盖（飞书）

| 编号 | 需求描述 |
|------|----------|
| F2.1 | **飞书私聊**：文本斜杠与私聊自定义菜单点击，全量指令均可触达且可成功执行（在 F1 权限规则下） |
| F2.2 | **飞书群聊**：用户 @ 机器人后发送的斜杠指令，与私聊**指令集合一致**；不因群聊场景单独禁止原管理员指令 |
| F2.3 | 群聊仍遵循既有**交互习惯**（如须 @ 机器人才受理）；本变更**不**将「取消 @ 要求」作为默认目标，除非产品另行确认 |
| F2.4 | 若通道未开启「允许他人使用」等准入策略，非授权用户仍无法与机器人对话——此为**通道准入**，与 F1 指令开放正交；须在帮助文案中区分说明（可选，设计阶段定稿） |

### 4.3 触达与文案

| 编号 | 需求描述 |
|------|----------|
| F3.1 | `/help` 输出：**不再**按角色列出两套指令表；展示用户**实际可用**的全量指令说明 |
| F3.2 | 飞书进入私聊帮助卡片：移除或改写「仅管理员」类标注；内容与 F3.1 一致 |
| F3.3 | 飞书私聊自定义菜单：管理员专属分组**不得**再作为权限门控；非管理员须能点击并成功执行原管理员菜单项（菜单是否合并为单一分组属体验优化，**不得**仅隐藏仍保留服务端拒绝） |
| F3.4 | 无权限类错误提示：若因通道未授权等非角色原因失败，提示须**可理解**，且不再出现「请联系管理员获取权限」类仅针对斜杠角色的文案（除非通道本身未开放） |

### 4.4 其他通道

| 编号 | 需求描述 |
|------|----------|
| F4.1 | **微信通道**是否同步执行 F1～F3 同等规则，见「七、风险与待确认」；若确认同步，微信斜杠路径与飞书**语义一致** |
| F4.2 | 若本期仅覆盖飞书，须在 `/help` 或发布说明中标注微信仍沿用旧规则（临时方案，需产品确认） |

## 五、非目标

| 编号 | 说明 |
|------|------|
| NG1 | **不**在本 PRD 定义实现细节、模块落点或接口（归属 `/kb-design`） |
| NG2 | **不**默认修改通道级准入策略（如「仅主用户私聊」「allowOthers 是否开启」）；用户能否与机器人**说话**仍由通道配置决定 |
| NG3 | **不**默认取消飞书群聊 @ 机器人的交互要求（除非产品单独立项） |

| NG5 | **不**在本期重构飞书后台自定义菜单的物理分组与 event_key（可顺带调整文案与可见性，但不强制重做菜单结构） |
| NG6 | **不**将本变更与「飞书展示与控制层」等架构演进绑定验收；仅聚焦远程指令权限与触达一致性 |
| NG7 | **不**承诺为企业级 RBAC、审计日志、操作审批等**细粒度治理**（若开放配置类指令后需要，应单独立项） |

## 六、验收标准

以下标准关注**用户可感知**结果，可通过飞书私聊与群聊实际操作验证。

### 6.1 指令开放 — 私聊

1. 非主用户飞书私聊发送 `/workspace`、`/model`、`/list`、`/chat new` 等原管理员指令，**成功执行**或返回与参数/上下文相关的业务错误，**不得**仅因非管理员被拒绝。
2. 非主用户点击原「管理员指令」菜单项（工作区、模型、新建临时会话等），结果与主用户点击**一致**。
3. `/help` 与进入私聊帮助卡**不**再将部分指令标为「仅管理员」；所列指令与非主用户实际可执行集合**一致**。

### 6.2 指令开放 — 群聊

4. 通道已允许该用户群聊对话的前提下，非主用户在群聊 @ 机器人后发送原管理员指令，行为与私聊**一致**（成功或业务错误，非角色拒绝）。
5. 主用户在群聊与私聊可用的指令集合**相同**（均为全量）。

### 6.3 原基础指令不退化

6. `/help`、`/status`、`/reset`、`/stop` 对全体用户仍可用；`/stop` 行为符合「七、风险与待确认」中最终产品决策。
7. 手动输入斜杠与菜单点击**双路径**均保持可用，开放权限后**不破坏**既有文本路径。

### 6.4 错误与边界

8. 通道未授权用户（如未开启 allowOthers 的他人私聊）仍无法对话；此时提示指向**通道配置**，而非「斜杠管理员权限」。
9. 不存在「菜单可点但文本斜杠被拒」或「私聊可用、群聊不可用」的**同一指令**分裂体验（通道未开放除外）。

### 6.5 微信（若纳入本期）

10. 若产品确认微信同步：微信私聊/群聊下非主用户可执行全量指令，验收方式同 6.1～6.4 的通道等价场景。
11. 若微信不纳入本期：文档或帮助中**明确**标注范围，且飞书验收 1～9 仍须全部通过。

## 七、风险与待确认

| 编号 | 主题 | 说明 |
|------|------|------|
| **R1** | **`/stop` 停止范围** | 现网：管理员 `/stop` 可停**全部**运行中任务，普通用户仅停**本会话**。全员开放后是否改为「人人停全部」或「人人仅停本会话」或「按会话归属智能停止」？**须产品确认**，否则验收标准 6.3 无法闭合 |
| **R2** | **配置类指令安全风险** | `/workspace`、`/model`、`/mcp`、`/restart`、`/clean` 等可改变运行环境、清空队列或重启进程。对任意用户开放后，是否存在误操作、恶意清队列、切换至敏感目录等风险？是否需二次确认、操作范围限制或审计？**须产品确认**接受的风险等级与缓解策略 |
| **R3** | **微信通道是否同步** | 用户需求未明确微信。若仅改飞书，微信仍二分权限，会造成**跨通道体验不一致**。**须确认**本期范围：飞书 only / 飞书+微信同步 |
| **R4** | **与通道准入的边界** | 用户可能理解为「全员指令 = 任何人都能用机器人」。若通道仍限制「仅主用户」或「未 allowOthers 的群聊」，非授权用户仍无法触达指令。**须在帮助或发布说明中写清** |
| **R5** | **群聊 @ 与指令开放** | 开放指令不等于取消 @；协作群中的误触、刷屏风险仍在。**须确认**是否需额外节流或确认（本期非目标，但需知晓） |
| **R6** | **菜单与帮助文案发布** | 飞书后台菜单结构、帮助卡内容若仍含「管理员」字样，会造成感知与行为不一致；需与 F3 一并验收 |
| **R7** | **任务/工作流指令影响面** | `/task`、`/workflow` 可能触发独立 Agent 或改变调度；开放给任意用户后的资源消耗与并发上限**须评估** |
| **R8** | **与近期菜单变更的关系** | 近期已上线私聊菜单的「管理员分组」产品语义；本变更将**反转**该分组权限含义，需评估是否合并菜单、更新对照表与扫码权限说明 |

## 八、与现有能力的关系

- **远程斜杠指令体系**：本变更**不改变**各指令的业务含义，仅**取消角色门控**并统一私聊/群聊可用集合。
- **飞书私聊自定义菜单**：菜单仍是指令触达方式；权限开放后须与文本斜杠、帮助文案**三者一致**。
- **通道准入（allowOthers 等）**：决定「能否与机器人对话」；本变更决定「对话后能发哪些指令」。两层规则并存，产品说明须清晰。
- **CardKit 与会话内控制**：合并预览、流式回复、卡片按钮等**不在**本变更验收范围内，但不得因权限改动而回退。
