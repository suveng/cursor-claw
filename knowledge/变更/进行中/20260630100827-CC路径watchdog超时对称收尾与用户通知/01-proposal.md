## 背景与问题

Cursor Claw 支持 **Claude Agent（CC）** 与 **Cursor SDK** 两条 Agent 执行路径。用户通过飞书、微信等 IM 通道发起对话后，后台调度 Agent 处理请求；通道侧会展示「Agent 处理中…」等进度反馈，Run 结束时应回到可继续对话的空闲状态。

**用户反馈**：在 Claude Agent 路径下，当任务（含子 Agent / 长时间工具协作）持续较久且通道侧长时间无新输出时，Run 会被系统 **静默中止**——用户侧往往 **看不到明确的超时说明**，仍停留在「处理中」或误以为任务仍在进行，随后发新消息可能受阻或体验与 Cursor SDK 路径不一致。

**现状问题（产品视角）**：

1. **超时强杀但用户无感知**：Claude Agent 路径在 watchdog 判定超时后会中止当前 Run，但 **未向 IM 通道推送可读的失败/超时说明**；用户可能仅见进度停滞或「处理中」长期不结束。
2. **与 Cursor SDK 路径体验不对称**：Cursor SDK 路径在平台/Run 超时时有 **明确的收尾与用户通知**（含友好提示、进度展示结束、会话可继续）；Claude Agent 路径 **缺少对等行为**，双引擎用户感知不一致。
3. **长任务静默期易被误判**：当子 Agent 或工具执行阶段 **长时间不向通道推送新内容**（但后台仍在工作）时，系统可能按「无活动」判定超时并中止，用户 **无法理解** 为何任务被中断。
4. **超时后会话恢复不完整**：超时中止后，会话未必自动回到 **可直接发新消息** 的空闲状态，或与 Cursor SDK 路径的「超时后可重发继续」体验不一致。

**关联变更（说明关系，非本变更范围）**：

| 变更 | 关系 |
|------|------|
| Claude Agent SDK 落地（已归档，含遗留债务） | 本问题出现在 SDK 落地后的 Claude Agent 执行路径；本变更补齐其超时收尾与用户通知缺口 |
| Agent Run 超时自动停止（已归档） | 已定义 IM 路径 Run 超时后的自动停止与会话恢复产品要求；本变更要求 Claude Agent 路径 **对齐同等产品行为** |
| 多轮调度超上下文与超时取消降故障（已归档） | 引入 RunGuard/watchdog 收敛能力；本变更聚焦 Claude Agent 路径 watchdog 超时后的 **用户可见收尾** |

## 目标用户与场景

### 目标用户

- **IM 通道日常用户**：通过飞书/微信与绑定 Claude Agent Profile 的通道对话，期望长任务有合理边界且失败可理解。
- **长任务 / 子 Agent 使用者**：发起多步工具协作、子 Agent 委派等 **可能长时间无通道输出** 的请求，更容易触及 watchdog 边界。

### 场景 A：长任务静默后 watchdog 超时

用户发送复杂请求，通道先展示进度或流式片段，随后 **较长时间无新输出**（子 Agent 或工具在后台执行）。约数分钟后 Run 被系统中止。**现状**：用户 **未收到** 明确超时说明，「处理中」类展示可能 **未及时结束**。**期望**：系统 **主动告知** 本次处理已因超时结束，进度展示停止，会话恢复为可发新消息状态。

### 场景 B：超时后与 Cursor SDK 路径体验一致

同一用户分别在 Claude Agent 与 Cursor SDK 路径下触发可复现的超时场景。**期望**：两条路径在 **用户可见结果** 上对称——均有超时类友好提示（或等价一次通知）、进度结束、**无需 Stop/Reset 即可重发消息** 继续对话。

### 场景 C：绝对时长上限与空闲超时的用户理解

Run 自启动起存在 **总时长上限**，同时存在 **无通道活动** 的空闲超时。**期望**：对用户而言，无论触发哪一种超时，**收尾行为一致**（停止 Run、结束进度、可选一次友好说明、会话可继续），且文案能体现「已因超时结束、可重新发送消息」，而非技术日志或未翻译的内部状态。

### 场景 D：子 Agent 静默期不误杀（产品期望）

子 Agent 或工具执行期间，通道可能 **长时间无新消息** 但任务仍在进行。**期望**：产品在 **合理静默窗口** 内 **不** 因「无 IM 可见输出」 alone 而中断仍有效的后台工作；若确需超时，边界与 Cursor SDK 路径 **语义对齐**，且用户收到 **可理解的说明**。

## 功能需求

### F1 超时对称收尾

- Claude Agent 路径在 watchdog 判定 **空闲超时** 或 **绝对时长超时** 时，须执行与 Cursor SDK 路径 **对等的 Run 收尾**：结束当前 Run、停止向 IM 推送该 Run 的进度/流式/工具卡片、将会话调度状态恢复为 **可受理新消息**。
- 收尾须 **确定终态**，不得长期悬挂在「处理中」或异常占用。

### F2 用户可见 IM 通知

- 超时中止时，须向用户 IM 通道发送 **一条** 简体中文友好提示，语义包含：**本次处理已因超时结束**、**可重新发送消息继续**（或与 Cursor SDK 路径超时提示 **同等可读性**）。
- **禁止** 向用户展示内部日志原文、未翻译的技术字段或堆栈。
- **禁止** 对同一超时事件重复、连续推送多条同义失败通知。

### F3 超时语义与双路径对齐

- **空闲超时** 与 **绝对时长超时** 对用户的收尾行为须 **一致**（F1/F2 均满足）。
- Claude Agent 与 Cursor SDK 两条路径在超时场景下的 **用户感知** 须对齐：均有明确结束信号与会话可继续性，避免「一条路径有说明、另一条静默强杀」。

### F4 长任务 / 子 Agent 静默期的活动策略

- 当后台任务（含子 Agent）仍在有效执行、仅 IM 通道暂时无新输出时，产品须定义 **与 Cursor SDK 路径一致的「仍算活动中」策略**，避免合理长任务被过早误判为空闲超时。
- 若确因策略边界触发超时，仍须满足 F1/F2。

### F5 稍后发消息可继续（核心）

- 超时收尾完成后，用户 **在同一会话** 直接发送新消息，**无需** 手动 Stop Agent 与 Reset，新 Run **正常启动** 并产生回复（或明确的非超时类失败，但 **不** 被上一轮超时残留状态阻塞）。

## 边界与不在范围

- **用户主动取消**：Stop 或取消指令路径沿用既有行为；本变更 **不** 将主动取消与超时停止混为一谈。
- **非超时类失败**：工具异常、网络中断、权限拒绝等沿用既有失败路径；本变更 **不** 统一所有失败类型文案。
- **调整超时阈值数值**：是否将 5 分钟改为其他具体数值 **可在设计阶段评估**；本 PRD 要求的是 **超时已发生时的收尾、通知与双路径对齐**，不限定最终毫秒数。
- **新增设置页或视觉改版**：无新增界面（Figma：无）。
- **技术实现细节**：本阶段不限定具体模块、函数或日志字段；设计阶段再展开。

## 验收标准

1. **可复现超时收尾**：在 Claude Agent 路径下构造 **空闲超时** 与 **绝对时长超时** 各至少一种可复现场景；系统在判定超时后 **数秒内** 结束 Run，会话 **不** 长期停留在处理中或异常占用。
2. **IM 超时通知**：上述两种场景下，用户 IM 通道 **均收到一条** 简体中文超时友好提示，语义符合 F2；**无** 内部日志原文或重复多条同义通知。
3. **进度展示结束**：超时收尾后，通道侧「处理中 / 进行中 / 流式占位」等展示 **同步结束**，用户 **不** 误以为任务仍在运行。
4. **稍后发消息可继续（核心）**：超时收尾完成后，用户 **不执行 Stop/Reset**，在同一会话发送新消息，新 Run **正常启动** 并产生回复。
5. **双路径对称（抽样）**：在可对照条件下，Claude Agent 与 Cursor SDK 路径各触发一次超时场景，对比确认：**均有** 用户可见超时说明（或等价通知）、进度结束、会话可继续；**无** 「仅 CC 路径静默强杀、SDK 路径有说明」的明显落差。
6. **子 Agent 静默（产品向）**：构造「子 Agent 或长工具执行、通道长时间无新输出但任务仍有效」场景；在 **与 SDK 路径一致的合理窗口内** **不** 发生误杀；若边界外仍超时，仍满足验收 1～4。
7. **主动取消无回归**：用户主动 Stop 后行为与变更前一致；**不** 误走超时专用收尾导致状态错乱。
8. **非超时失败无回归**：任选一条非超时失败用例，确认 **不** 误用超时专用文案，既有失败路径仍可用。
