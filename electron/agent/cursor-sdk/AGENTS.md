# agent/cursor-sdk/ — Cursor SDK Run 边界

## Cursor SDK Run 模块边界

- **入口编排**：`agent-sdk.ts` launch/dispatch/HTTP 路由；复杂逻辑下沉 `sdk-run-*`；**单文件 ≤300 行**。
- **bind 后预热**：`sdk-warmup.ts` — `warmupSdkAfterBind` fire-and-forget；日志关键字 `sdk_warmup`；调用方 void 不 await。
- **事件流 SSOT**：`sdk-run-stream.ts` — `streamRunEvents`+`handleSdkEvent`；终态 status/超时/取消经 `RunEvent`→`applySdkStreamRunEvent`（非直调 `notifySdkFailure`）；运行期仅 `for await (run.stream())`；`run.wait()` 仅 `finalizeRunContextUsage`/`completeSdkRun` 收尾。
- **Engine Port**：`engine-port-adapter.ts` — Cursor `AgentEnginePort` 六方法；`registerCursorEnginePort` 于 `ensureAgentSdkHttpServer` 注册 `sdk`；`sdk-run-port-lifecycle.ts` 承载 `RunLifecycle` 缓存（`getOrCreateSdkRunLifecycle`）、`applySdkStreamRunEvent`、`completeSdkRunViaPort`、busy IM（`notifySdkProcessingBusy`）。**禁止**在 adapter/`sdk-run-port-lifecycle` 外平行实现完整终态 lifecycle。
- **生命周期**：`sdk-run-lifecycle.ts` — `startSdkRun`（Port watchdog+Lifecycle+stream）、`completeSdkRun`→`completeSdkRunViaPort`、`stopSdkSession`（`markSdkRunUserStopped`+abort）；终态失败/超时/取消统一经 `sdk-run-finalize.completeSdkFailureViaTemplate` → `RunLifecycle.enterNotifying`。
- **watchdog**：`sdk-run-watchdog.ts` — `armRunWatchdog`；idle 默认 **30min**（`SDK_IDLE_TIMEOUT_MS` 可覆盖），absolute 默认 7min（`SDK_RUN_WATCHDOG_MS`/`PLATFORM_RUN_LIMIT_MS`），二者解耦；`NEVER_CANCEL_ON_DURATION` 默认 true 不按总时长硬杀；`tool_running`/`awaiting_user`/`lastTool.running` 豁免 idle 取消（对称 CC）。**`watchdogTimedOut`**（`sdk-session-types.ts`，对称 CC）：`onTimeout` 在 `cancelRunAndWait` **前**置 `true`；用户 `stopSdkSession`（aborted）**不**置闩；`resetSdkRunPresentationState` 清零。**`markSessionActivity` 门控**（`sdk-session-registry.ts`）：`watchdogState==='cancelling'` 或 `watchdogTimedOut` 时仅刷新 `lastActivityAt`，**禁止** `activity_resume`（防 stream `CANCELLED` status 复活 watchdog）。
- **持久化**：`sdk-run-persistence.ts` — `userData/sdk-active-runs.json` 读写；`sdk-run-persist.ts` 呈现游标 3s 节流写盘。
- **续接（S7，仅 Cursor）**：`sdk-run-recover.ts` — `recoverSdkActiveRuns`（`Agent.resume`+`Agent.getRun`→`getOrCreateSdkRunLifecycle().resume()`+`enterGuardWithLifecycle`→`startSdkRun`）；`notifyResumeFailure` 一次 IM 提示；`daemon/daemon-manager` init 挂接。CC/Codex/OpenCode 仅有 SDK 内 resume 续上下文，无主进程重启 recover。
- **呈现/收尾/分发**：`sdk-run-presentation.ts`（stream-text/PRESENTATION_ORDERING）、`sdk-run-finalize.ts`（超时/失败 notify）、`sdk-run-dispatch.ts`（sendWithRetry）、`sdk-resident-refresh.ts`（空闲刷新）、`sdk-opaque-retry.ts`（静默 ERROR 一次重试）。
- **会话注册表**：`sdk-session-registry.ts`+`sdk-session-types.ts` — `sdkSessions` Map、`markSessionActivity`（含 watchdog 闩门控）、`runPhase`、`watchdogTimedOut?`；`agent-sdk.ts` re-export 查询 API。
- **统一网关 SSOT**：`agent-sdk-http.ts` 的 `launchSdkAgentFromHttp` / `dispatchAgentFromHttp` 为四引擎 launch/dispatch 唯一网关；**双入口汇入** — IM 经 Daemon `forwardElectronAgentApi`→`/api/agent/launch|dispatch`，本地任务/工作流/`/chat new` 经 `session-dispatcher.launchAgent` 进程内调用 `launchSdkAgentFromHttp`（避免 Electron→Daemon→Electron 三角跳转）。按 `resolveBoundAgentResourceType` 委托各引擎 handler。`ensureAgentSdkHttpServer` 由 `daemon-manager` init 常驻，端口 `userData/agent-api-port.json`。**斜杠同步执行**：`POST /api/command/execute` 注册于同 server，handler 落 `agent-command-http.ts`，复用 `executeFileCommand`（不经 `.fcmd`）。**MCP 健康探测**：`POST /api/mcp/status-map` 同 server 注册，请求 `{ workspaceDir?, force? }`，响应 `{ ok, statusMap }`；handler 直接 `getMcpStatusMap`（`mcp-manager`），供 Daemon `fetchElectronMcpStatusMap` 对接。
- `agent-sdk.ts`：SDK 生命周期与事件流；通知 daemon 时用 `daemon/daemon-client.httpPost`，避免与 `session/session-dispatcher` 循环 import。

## SDK 流式与 Presentation

- **SDK 流式桥接（f41Eligible）**：主用户私聊或飞书群聊（`allowOthers`）+ SDK 资源时，`handleSdkEvent` assistant delta → `POST /api/stream-text`（累积全文、400ms 节流）；首包不带 `outbound_message_id`，后续回传 daemon 返回值。`flushStreamPost` 经 `session.streamPostChain` 串行 in-flight：每次 POST 入链并 await 上一包完成后再发，避免并发首包；`final` 包同样入链末尾，且携带 `message_id`（当次 claim 末条 inbound id，经 launch/dispatch `message_ids` → `session.inboundMessageIds`）。会话结束或 `stopSdkSession` 时 `resetStreamPostChain` 清 timer 与链。非 f41Eligible 仍走 `appendSdkLog`，不调 stream-text。eligible 须与 Daemon `isStreamTextEligible` 一致。
- **Presentation 时序编排（PRESENTATION_ORDERING）**：`presentationOrderingEligible(session)` = 开关开启 **且** `f41Stream`（主用户私聊或飞书群聊 SDK）。`markProcessEventSeen(session, kind)` 在门控通过时对 **thinking / tool / task** 均置 ordering 闩（`seenProcessEvent`/`presentationDeferStream`）；**呈现抑制（daemon 里程碑降级）≠ 不参与 ordering defer**——Electron 仍 POST `presentation-event` 并置闩。**ordering 闩锁与 Rev2 分工**：闩锁仍标记「含过程应 defer assistant」；Rev2 将 release 时机从过程 idle 改为 Run final 唯一出站（闩锁语义不变、release 路径变更）。含过程 Run 内 assistant delta 只累积 `streamBuffer` 不 `scheduleStreamPost`；首包未见过程事件时 `schedulePreambleRelease`（400ms 与 stream 节流对齐）短窗等待过程事件，`doFlushStreamPost` 非 final 复检 `shouldDeferAssistantPost`；过程事件 `clearStreamPostTimer`。thinking 结束 `closeThinkingIfOpen` 传 `final: true`（`maybeReleaseDeferredAssistant` 在 end-only 下为 no-op）；**task 只置闩、不单独 release**。**Rev2 end-only assistant IM**：`shouldEndOnlyAssistantDefer(session)` = ordering 且已见过程（`seenProcessEvent`/`presentationDeferStream`）且尚无 `outboundMessageId`；为 true 时 `doFlushStreamPost` non-final、`flushDeferredStreamPost`、`maybeReleaseDeferredAssistant` **均 no-op**——**禁止**过程 idle / thinking 结束等 mid-run release，不向 Daemon POST 首建或 PATCH。**Run 收尾**（`streamRunEvents`）：`finalizeRunContextUsage` 后仅 `flushStreamPost(session, true)` 为 ordering+含过程场景**唯一** assistant IM 出站（兼首建与流式完结）；收尾块无 `flushDeferredStreamPost`。daemon 返回 `deferred: true` 时设 `presentationDeferStream`。纯对话（始终无过程事件）经 preamble 短窗后 POST，不额外延迟于现网 400ms 节流。`resetSdkRunPresentationState` / `startSdkRun` 清零编排布尔与 buffer。
- **Presentation 出站（tool/thinking/task）**：`handleSdkEvent` 中 **thinking / task 事件始终** `POST /api/presentation-event`；**tool_call 仅 notify 白名单** POST，silent 不产生 `presentation-event`（见下节分级门控）。`postPresentationEvent` **不因飞书抑制早退**——CardKit 抑制与里程碑降级在 daemon 处理。**task 双路径去重**（`sdk-tool-event-dedup.ts`）：相邻同参 `tool_call running` 跳过重复日志/IM；`task` 事件若与刚处理的 `task` tool_call 语义等价则跳过。**tool_call 分级门控**（SSOT：`src/shared/sdk-tool-presentation-tier.ts` → `resolveSdkToolPresentationTier`）：`notify`（shell / write / strreplace / delete / task 工具名）→ `markProcessEventSeen` + `postPresentationEvent`（`running` 清 `toolPresentationOutboundIds`；非 running 时 `maybeReleaseDeferredAssistant`，Rev2 下 `shouldEndOnlyAssistantDefer` 时为 no-op）；**notify tool_call 载荷**：`extractShellPresentationFields` / `extractTaskPresentationFields` 展开 `tool_shell_command` / `tool_task_description` → daemon `formatToolMilestoneText`（shell `started` 含命令摘要；task `started` 含 `description`，禁止裸 `task：已开始`）；`silent`（read / glob 等未命中白名单，默认）→ **跳过** `markProcessEventSeen` 与 `postPresentationEvent`，但 `pushUiLog` `[tool]` 与 `session.lastTool` **仍全量**。**thinking**：`markProcessEventSeen` → `postPresentationEvent`（飞书 daemon **零里程碑出站**；桌面 `[thinking]` 日志保留）。**task 事件**（非 tool_call）：`status=started` 递增 Run 级 `session.taskSeq`；`mapTaskMilestoneText(status, text, taskSeq)`（started+text→`正在执行：{截断}`；无 text 有 seq→`子任务 #N 已开始`；无 text 无 seq→`子任务已开始`）→ **`markProcessEventSeen(session, "task")` 在 `postPresentationEvent` 之前**（与 thinking/tool 对称置闩；不单独 release）→ `postPresentationEvent({ kind: "task", task_status, task_text })`。飞书 tool 里程碑文案 SSOT：`formatToolMilestoneText`（`src/shared/tool-presentation.ts`）。**本变更不修改** `sdk-run-presentation.ts` Rev2 end-only 链。assistant 正文仍仅走 stream-text。PRESENTATION_ORDERING 与 `f41Stream` 对齐（主用户私聊 + 飞书群聊）。
- **SDK 错误 notify**：终态失败经 `completeSdkFailureViaTemplate`（`sdk-run-finalize.ts`）→ `createRunLifecycle` → `enterNotifying` → `completeRunFromTemplate` → `notifySessionChat(..., stop_progress: true)`；富文案由 `buildSdkFailureText`（`formatRunFailureMessage` + context footer）经 `failureText` 传入。流式路由：`applySdkStreamRunEvent`（`sdk-run-port-lifecycle.ts`）将 `RunEvent` 终态转上述路径。**pre-send 阻断**：`notifyPreSendContextFailure` 即时 IM（非终态模板路径）。**失败归因**（`RunFailureReason`）：`timeout` → `context_exhausted` → `session_abnormal` → `run_error` 等，组装逻辑仍在 `sdk-failure-messages`/`buildSdkFailureText`。路径：`streamRunEvents` catch、`applySdkStreamRunEvent`、`completeSdkRun` 失败分支、`finalizeSdkRunOnTimeout`（`finalize-sdk-run.ts`）。stack/tool 名仅 UI 日志；用户 `stopSdkSession`（aborted）不 notify。**watchdog 竞态**：`watchdogTimedOut || runFinalizing` 时跳过重复终态 notify。`runFinalizing` 幂等；`completeSdkRun` 已收尾则跳过。
- **SDK error 可观测性**：`handleSdkEvent` 在 `tool_call` 时写入 `session.lastTool`；`run.status === "error"` 时 UI 日志单行 `运行错误详情:` 含 `sessionKey`、`agentId`、`durationMs`、`lastTool`、`run.result`、`errorCode`、`waitResult` 等结构化字段。
- **保活失败文案（F3.2）**：超时类由 `isRunTimeoutFailure` 判定后 `formatUserSdkFailureMessage` 输出「会话因等待超时已退出…」（含 F3.2 shell:running + duration≥20min、平台长时 ≥7min）；`isTimeoutFailure` 分支**优先于** CANCELLED 固定「任务已取消」句。`notifySdkFailure` 用 `run`/`runStartedAt` 解析 duration。平台长时 `CANCELLED/ERROR/EXPIRED` 经 finalizer 即时 notify；短 ERROR 走 `completeSdkRun`。非超时 tool/上下文失败走 `sdk-failure-messages` 归因。

## SDK MCP / 压缩 / 上下文

- **SDK MCP 内联**：`mcp/loaders/mcp-sdk-loader.loadInlineMcpServersForSdk` 仅 inline HTTP/sse/OAuth 依赖项；stdio/command 默认由 `settingSources` 加载（`SDK_MCP_STDIO_INLINE=1` 可回滚全量 inline）。`appendInlineMcpToSendOptions` 内部调用筛选函数。三处注入点（`launchSdkAgent`/`buildSendOptions`/`maybeRotateSessionForPressure`）统一使用 `loadInlineMcpServersForSdk`；`lastInjectedMcpServers` 仅含实际 inline 条目。启动/send 前 `pushUiLog` 输出 `[config] settingSources=project,user cwd=… inlineMcp=…`（S13 可观测）。
- **SDK 自动压缩**：`Agent.create` / `agent.send` 无显式 `autoCompress` 配置项；接近上下文上限时由 harness **默认** summarization/compression。`agent.send` 挂载 `onDelta`，`summary-started` / `summary-completed`（及 `summary`）写入 SDK UI 日志，前缀 `[compression]`。**pre-send 可观测**：`launchSdkAgent` / `dispatchToSdkAgent` 在 `resolveContextLimitForSession` 之后、`agent.send` 之前调用 `evaluatePreSendContextPressure` → UI 日志 `[compression] pre-send usage {pct}%`（≥85% limit）；`maybeRotateSessionForPressure` 同步写入 `lastPreSendUsedTokens`/`lastPreSendUsageRatio`。**pre-send 阻断**：ratio≥100% 且轮转未成功时 `sendWithRetry` 返回 `context_blocked`，不调用 `agent.send`。**turn-ended 高水位**：占用 ≥85% limit 时 `[compression] high-watermark {pct}%`（`context-usage-pressure` + `handleAgentSendDelta`）。
- **SDK 上下文 footer（IM 回复）**：**单一落点** `agent-sdk.ts` — Run 流结束后 `finalizeRunContextUsage` 读 `run.usage`（必要时 `run.wait()`），与 `onDelta` turn-ended 快照 **并排打 `[context-usage]` 日志**；`doFlushStreamPost(..., final=true)` 前 `applyContextFooterToBuffer` 写入 `streamBuffer`；中间 chunk 不含 footer。footer **优先** `run.usage.totalTokens`，不可得时回退 turn-ended/peak；格式 `\n\n---\n上下文：{p}% ({usedK}k/{limitK}k)`（有上限）或 `\n\n---\n上下文：已用 {usedK}`；上限来自 `Cursor.models.list` 或 modelId 启发式（session 级缓存）。`appendContextFooter` 对已含「上下文：」的正文幂等。CLI 路径不在 IM scope。
- **SDK 自动压缩飞书通知**：`summary-started` 经 `notifySessionChat` 下发「正在压缩上下文…」（与「Agent 处理中…」同语义，不传 `stop_progress`）；每 Run 至多一次（`compressionNotified`）；`summary-completed` 仅写 UI 日志。
- **SDK 长驻 Agent（`SDK_RESIDENT_AGENT`）**：默认开启；`SDK_RESIDENT_AGENT=0` 回退 Run 结束 `close()`。**非超时 error**：`completeSdkRun` 在 `residentMode` **保留**实例、`reportSessionAgentPhase(idle)` 触发 Daemon flush。**超时类**：`finalizeSdkRunOnTimeout` 后 `agent.close()` + 删 session（长驻与非长驻均清理），下条 launch 重建；**不写 `failedCooldowns`**。`isSdkSessionRunning` 仅 processing（`run`/`pendingDispatch`），idle 用 `hasSdkSession`。二次任务 `dispatchToSdkAgent`；`launchSdkAgent` 遇 processing 会话 WARN 早退 `{ ok: true }`。失败日志 `dispatch_failed` / `agent_failed`。`ensureAgentSdkHttpServer` 应用 init 启动，端口 `userData/agent-api-port.json`；Daemon 转发 `POST /api/agent/launch|dispatch`。**Daemon 统一入口路由**：`launchSdkAgentFromHttp` / `dispatchAgentFromHttp` 按 `resolveBoundAgentResourceType` 委托 — `claude-code` → `launchCcAgentFromHttp` / `dispatchToClaudeCodeAgent`，`sdk` → 现有 SDK 逻辑，legacy `cli` 绑定返回明确错误；与 `session/session-dispatcher.launchAgent` 双引擎口径一致。

## ContextRotation / 长驻空闲刷新 / 静默 ERROR 重试

- 轮转必须"先 `Agent.create` 成功，再替换 `session.agent`，最后 best-effort 关闭旧实例"；创建失败时保留旧实例继续 send，禁止先 `close` 再创建导致会话假存活。共用 `sdk-resident-refresh.recreateSessionAgent`。
- **ratio≥100%**：`context-rotation-lite` 跳过连续 2 次命中与冷却，首轮即轮转；ratio∈[90%,100%) 保留现网 2 次 + 冷却规则。
- **共享 workspaceDir**：`warnIfSharedWorkspaceDir` 多活跃 session 同目录时 WARN（每目录每进程 1 条），仅可观测不改行为。
- **resident-refresh**（`sdk-resident-refresh.ts`）：长驻且 `Date.now()-lastActivityAt ≥ RESIDENT_STALE_IDLE_MS`（15min）时，`sendWithRetry` attempt===1 先重建 Agent；日志 `[sessionKey] resident-refresh idle=…ms`；create 失败保留旧实例。
- **opaque_retry**（`sdk-opaque-retry.ts`）：`completeSdkRun` 遇静默早期 ERROR（无可用 message/result/errorCode、无 lastTool、duration<15s、本 turn usage≈0）且有 `lastSendText`、尚未 `opaqueRetryDone` 时，重建并重发一次；**不** notify、**不**写 `failedCooldowns`；成功则清旧 run 态后 `startSdkRun` 并提前 return；失败再走原 notify。`lastSendText` 在 send 前写入；`opaqueRetryDone` 由 `resetSdkRunPresentationState` 清零；opaque 成功路径在 `startSdkRun` **前**置 true；`startSdkRun` 不再清零该闩。
- **失败兜底文案**：非上下文静默失败用「临时故障，请重新发送」；上下文 peak/pre-send≥95% 仍用「上下文窗口已接近或达到上限」。

## IM 调度

- Daemon `POST /api/agent/launch|dispatch` 经 `agent-sdk.ts` 按通道资源类型路由（SDK / Claude Code）；无 CLI spawn、无 `poll-message`。
